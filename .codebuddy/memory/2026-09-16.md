## 生产库只读连通性测试（用户提供凭据，要求只查询）

**方法**：写一次性 vitest 探针，导入应用**真实服务类**（`ConnectionManager` + 同一 mysql2 工厂 + `SchemaCache` + `QueryService`）连生产库，全程 `readOnly()` 守卫（只允许 SELECT/SHOW/DESCRIBE/EXPLAIN），无写语句、无全表扫描。跑完删除探针与输出文件，工作区干净（已确认）。

**环境画像**
- 腾讯云 CynosDB MySQL `8.0.30-cynos-3.1.16.006`，hostname `TENCENT64.site`，server port 25572
- 连接 `testConnection` = ok，耗时 106ms
- 可见库 7 个；业务库：`ads_yewu`(23 表) / `ods_yewu`(46 表) / `finedb`(108 表)
- `lower_case_table_names=1`（表名大小写不敏感）、`time_zone=+08:00`、server 字符集 `utf8mb4_general_ci`
- 元数据查询 60~80ms；`SELECT ... LIMIT 5` 采样 63~73ms（远程性能良好）
- 账号对 `*.*` 具备 ALL 级权限（含 CREATE USER / DROP / GRANT OPTION）→ 权限过宽，需提醒

**通过项（应用真实代码路径）**
- `SchemaCache.listDatabases/listTables/getColumns/getDdl` 全部正常，列注释能正确回填
- MySQL 8.0 兼容 `SHOW FULL COLUMNS FROM tbl FROM db` 旧式双 FROM 语法（列浏览依赖它）
- `executeMany` 多语句路径正确返回 3 个独立结果集
- 会话字符集 client/connection/results 均为 utf8mb4；`中文测试😀` 往返无损
- 日期归一化修复被真机验证：`DATETIME '2026-09-16 00:00:00'` → 保留时间；`DATE` → 仅日期
- DECIMAL 由 mysql2 返回字符串（精确，如 `"1.25"`）

**发现的问题（均为 P2，未修改代码）**
1. `bit` 列（finedb 有 46 个）mysql2 返回 Buffer → UI 显示 `[二进制 1 字节]`，Excel 导出为字面量 `[BINARY]`；建议归一为 0/1
2. BIGINT 走 JS number，>2^53 静默舍入（实测 `CAST(9007199254740993 AS SIGNED)` → `9007199254740992`）；当前数据未触发（max AUTO_INCREMENT：ads 5731 万 / ods 1190 万），但共 118 个 bigint 列属潜在风险；修法 `supportBigNumbers/bigNumberStrings`
3. DECIMAL 在 Excel 导出被写成文本（共 895 个 decimal 列，金额列无法直接求和）
4. 账号权限过宽（安全建议）

**未做（环境限制）**：真实 GUI 端到端（需用户在客户端新建连接验证）；未对任何表做聚合/全表扫描。
