# SQL Studio UI 打磨方案

> 体检日期：2026-09-17
> 体检方式：读取全部设计令牌（`src/renderer/styles/theme.css` 3311 行）+ 用 `tests/e2e/ui-audit.mjs` 在 Chromium 中注入贴近生产库的假数据，逐主题渲染并**用计算样式逐区域核对**背景色。
> 截图证据：`docs/ui-screenshots/audit/`（8 张，三主题 + 空态 + 弹窗 + 面板 + 对象浏览器）

---

## 0. 一句话结论

**主题系统本身是健康的**——三套主题逐区域都正确生效，Monaco 编辑器也准确跟随（实测见 §1.2），所以不需要"修主题"。

真正的打磨空间集中在四处：

1. **信息层次与深度不足** —— 深色下 6 层表面挤在约 10 级明度内，靠实心深灰 1px 边框撑结构，整体像"线框图"而非"工作台"
2. **结果网格的表格工程学** —— 数字左对齐、表头注释与列名抢视觉、没有行定位手段
3. **工具栏冗余** —— 编辑器上方堆了三层横条，其中一层右侧几乎全空
4. **品牌色彩不一致** —— 三套主题三个色相家族；编辑器（紫+青+绿）与外壳（蓝）是两套色彩语言

### 1.3 诊断：真正该改的 14 处

按"用户可感知程度"排序。

#### P1 · 高感知

| # | 问题 | 证据 |
|---|---|---|
| 1 | **编辑器上方堆了三层横条** | 标签行（`未命名-1 × +`）→ 文件操作行（`新建/打开/保存/另存为`，右侧约 70% 全空）→ 编辑器上下文行（`ads_yewu` + `格式化/AI/执行`）。三层约占 50px，其中一层承载极少信息 |
| 2 | **结果区信息与状态栏重复** | 结果面板底部与全局状态栏同时显示"耗时 412 ms / 行数 400"；两处都在窗口最下方 30px 内，读起来像被裁切 |
| 3 | **结果表头"两层信息抢戏"** | 列名 + 注释都用了粗体，且注释用高饱和绿（`sql-column` 色系）。13 列并排时变成一片绿字大标题，列名反而弱了 |
| 4 | **数字列左对齐** | `id`(bigint)、`order_count`(int) 都是左对齐。数据表里数值右对齐是扫描惯例，左对齐让人无法按位比较数量级 |
| 5 | **结果网格缺少行定位手段** | `.grid-row` 背景透明，没有斑马纹、没有行 hover 高亮、没有当前行指示。400 行横向滚动后极易串行 |
| 6 | **深色主题偏"扁平"** | 表面层级 `#16181d → #20242b` 只差约 10 级明度，且边框是**实心深灰** `#2c313b`。结果是"骨架清晰、体积感为零" |
| 7 | **品牌色在不同主题下换了三个色相** | 外壳主色 `#4f7fd9`（蓝）；Monaco 深色用 keyword `#7C8CF8`（紫）+ table `#00D9C8`（青）+ column `#34C77B`（绿）；Monaco 浅色用 `#6366F1`/`#0D9488`/`#16A34A`；钛灰用 `#4B6580`。**同一个产品有 4 套强调色家族** |

#### P2 · 中感知

| # | 问题 | 证据 |
|---|---|---|
| 8 | **排版令牌缺失** | 无 line-height / font-weight / letter-spacing。文档密度、标题层次全依赖浏览器默认值，是三套主题"气质差得不够开"的根本原因 |
| 9 | **等宽字体名不副实** | `--font-mono: 'JetBrains Mono', Consolas`，但**包里没有该字体文件**（`dist/renderer/assets` 只有 Monaco 的 `codicon-*.ttf`，源码 `@font-face` 计数为 0）。外观面板让用户选"JetBrains Mono"，实际静默回退 Consolas |
| 10 | **原生控件破坏一致性** | 外观面板的字体选择是原生 `<select>`（带系统箭头）；字号滑块 thumb 是个小圆点，hittest 偏小 |
| 11 | **空态缺少主动 CTA** | 中央只有一个约 28px 的线框数据库图标 + 两行文字，没有可点的主按钮，且文字淹没在超大空白里 |
| 12 | **窄侧栏里连接表单的提交按钮需要滚动才可见** | 侧栏宽约 217px，表单含 3 组 6 个字段，截图里可见到「字符集」为止，「保存 / 测试连接」在可视区外 |

#### P3 · 低感知但值得顺手修

| # | 问题 |
|---|---|
| 13 | 圆角 6/8/10px 对 12px 字号的密集工具偏"网页感" |
| 14 | 状态栏常驻「⚠ 密码为降级存储」占用永久视觉位。（原「bit 列显示 `[二进制 1 字节]`」**已于 2026-09-17 修复**：BIT 列在 `query-service.rowsToCells` 归一为 0/1，仅真正的 BLOB 保留二进制标记） |

## 2. 四个设计方向（选一个作为基调）

| 方向 | 气质 | 为什么适合 SQL 工具 | 代价 |
|---|---|---|---|
| **A. Linear（推荐）** | 近黑画布 + 半透明白边框 + 唯一靛紫品牌色 + 字号阶梯字距 | 密度高、克制、不喧哗；"深色不是给浅色设计套一层黑，而是原生介质"——正是专业工具要的感觉 | 需重做整套明度阶梯与边框模型 |
| **B. IBM Carbon** | 企业级数据表格、显式密度档位、结构化蓝 | 结果网格可以直接照搬它的表格规范（行高/对齐/斑马纹/固定列/密度三档），最省心 | 视觉个性偏"甲方企业风"，chrome 不够精致 |
| **C. Raycast / Cursor** | IDE 暗色 chrome + 命令面板 + 渐变点缀 | 开发者审美认同度高，容易做出"想截图分享"的效果 | 渐变/发光与当前"已清除磨砂+glow"的克制原则冲突，过度容易显廉价 |
| **D. Vercel** | 黑白精准、Geist 字体、极致简约 | 最安全的中性方案，几乎不会做错 | 缺少品牌记忆点，容易"哪都像" |

### 推荐：A 为主基调 + B 的表格规范

外壳/排版/深度走 Linear，结果网格走 Carbon 的表格工程学。两者不冲突：Linear 管"容器与语言"，Carbon 管"密集数据的可读性"。

### Linear 关键令牌摘录（`技能库 references/linear.app.md`）

**色彩 · 明度阶梯（深色原生）**

| 角色 | 值 |
|---|---|
| 最深画布 | `#010102` / `#08090a` |
| 面板 | `#0f1011` |
| 抬升表面 | `#191a1b` |
| 次级表面（hover） | `#28282c` |
| 边框（默认） | `rgba(255,255,255,0.05)` |
| 边框（标准） | `rgba(255,255,255,0.08)` |
| 主文本 | `#f7f8f8`（**不用纯白**） |
| 次文本 | `#d0d6e0` |
| 弱文本 | `#8a8f98` |
| 最弱文本 | `#62666d` |
| 品牌靛紫 | `#5e6ad2`（bg）/ `#7170ff`（accent）/ `#828fff`（hover） |

**排版 · 三档字重体系**：400（阅读）/ **510（UI 与强调，招牌字重）** / 590（强强调）；**最大字重 590，不用 700**。字距随字号收紧（32px 时 -0.704px，16px 以下回归 normal）。

**圆角阶梯**：2px（徽标/工具栏按钮）/ 4px（列表项）/ 6px（按钮、输入框）/ 8px（卡片、下拉）/ 12px（面板）/ 9999px（chip）。

**深度哲学（关键）**：暗色下阴影几乎不可见，**用半透明白边框 + 背景明度阶梯表达层级**，而不是加深阴影。按钮底色永远接近透明（`rgba(255,255,255,0.02~0.05)`）。

**Don't 清单**：不要用纯白 `#ffffff` 当主文本；不要用实心色做按钮底；不要用实心不透明深色边框；不要用 700 字重；不要在 chrome 里引入暖色。

## 3. 通用打磨清单（不依赖方向选择）

这一节是**无论选哪个方向都该做**的部分，也是本轮投入产出比最高的部分。

### A. 布局：三层横条 → 两层

```
现状（3 层，约 50px）                      建议（2 层，约 34px）
┌──────────────────────────────┐          ┌──────────────────────────────┐
│ 未命名-1 ×  │ +              │          │ 未命名-1 × │ +   ⟳ 💾 ⇩ ⌥   │
├──────────────────────────────┤          ├──────────────────────────────┤
│ 新建 打开 保存 另存为   (全空) │          │ ads_yewu ▾ │ ≡ 格式化  AI ▶ 执行│
├──────────────────────────────┤          ├──────────────────────────────┤
│ ads_yewu  │ 格式化 AI ▶ 执行  │          │  SELECT * FROM ...           │
├──────────────────────────────┤          │                              │
│  SELECT * FROM ...           │          │                              │
```

- 文件操作（新建/打开/保存/另存为）并入标签行右侧，改为图标按钮 + tooltip（保留文字的无障碍标签）
- 编辑器上下文行保留"库选择 + 格式化 + AI + 执行"，右侧可补「行/列」信息
- 结果面板页脚的"耗时/行数"与全局状态栏**只保留一处**（建议留状态栏，结果面板页脚只留"显示 N 行 / 被筛选隐藏 M 行"）

### B. 结果网格（Carbon 规范）

1. **数字列右对齐**：`bigint / int / decimal / float / double` 一律右对齐 + 等宽数字（`font-variant-numeric: tabular-nums`）
2. **表头降噪**：列名 12px / 字重 510 / 主文本色；注释或类型降到 10px / 字重 400 / `--color-text-muted`，**去掉绿色**。选中列或排序列才用品牌色
3. **行定位**：行 hover 用 `--color-surface-hover`，选中行用 `--color-surface-selected`；可选斑马纹（`nth-child(even)` 用 2% 明度差）
4. **固定首列**：横向滚动后保留行标识（PK 列或第一列）
5. **列宽启发式**：短值列（`country`）按表头宽度收敛，长串列给 ≥120px；当前 `asin` 被截断说明启发式偏保守
6. **单元格表达**：`NULL` 用斜体弱化（区别于空字符串）；真正的 BLOB 二进制改为 `0x414243…(3B)` 形式（**bit 列已修复为 0/1**，前端无需再处理）

### C. 色彩与深度（令牌级重写）

**深色（建议值，Linear 模型）**

```css
--color-canvas:        #0f1011;   /* 最深画布（编辑器/结果区底） */
--color-surface:       #16181a;   /* 面板 */
--color-surface-raised:#1c1e21;   /* 抬升表面、下拉 */
--color-surface-hover: rgba(255,255,255,0.04);
--color-surface-selected: rgba(255,255,255,0.07);
--color-border:        rgba(255,255,255,0.06);   /* 半透明，替代实心 #2c313b */
--color-border-strong: rgba(255,255,255,0.10);
--color-text:          #f7f8f8;
--color-text-secondary:#d0d6e0;
--color-text-muted:    #8a8f98;
--color-text-disabled: #62666d;
--color-primary:       #5e6ad2;
--color-primary-hover: #7170ff;
--color-primary-soft:  rgba(94,106,210,0.16);
```

**浅色/钛灰**：把边框模型对称换成 `rgba(0,0,0,0.06/0.10)`，品牌色保持**同一色相**（`#5e6ad2` 浅色下用 `#5865e0`），只调明度与软底色——这样"换主题"是同一设计的明度变体，而不是换了个产品。

**统一 Monaco 与外壳的色彩语言**：让 `SQL_STUDIO_THEME*` 的 `keyword` 对齐品牌靛紫（`#7170ff` / `#5865e0`），`sql-table`/`sql-column` 降为同一色相的明度差或统一中性青，去掉"紫+青+绿"三色并置。

**圆角收敛**：控件 4px / 面板 6px / 弹窗 8px / chip 9999px。

### D. 排版

补上现在完全缺失的三组令牌：

```css
--lh-tight: 1.25;  --lh-base: 1.45;  --lh-relaxed: 1.6;
--fw-normal: 400;  --fw-medium: 510;  --fw-semibold: 590;
--ls-tight: -0.01em;  --ls-normal: 0;  --ls-wide: 0.04em;   /* wide 用于小号大写标签 */
```

- 表格/列表行用 `--lh-tight`，帮助文本用 `--lh-relaxed`
- 表头、分组标题改为 `10-11px + uppercase + --ls-wide`，这是"工具感"最廉价也最有效的一招
- **等宽字体落地**：要么把 JetBrains Mono（OFL 授权）打进包，要么把外观面板的选项改成真实存在的项（`系统等宽` / `Consolas` / `等距更纱` 之类），不要让用户选一个不存在的字体

### E. 组件细节

| 组件 | 改法 |
|---|---|
| 原生 `<select>` | 自绘下拉（可复用现有 Modal/菜单样式），与自定义 UI 一致 |
| 字号滑块 | thumb 直径 ≥14px，轨道 4px，加刻度与当前值气泡 |
| 弹窗 | 遮罩加深到 `rgba(0,0,0,0.55)`；弹窗本体加 `1px` 半透明边框 + 分层阴影（Linear 的 Level 5 多层叠加），避免"浮不起来" |
| 空态 | 图标放大到 40px、透明度提高；加一个主按钮「新建脚本」+ 一个次级「打开文件」 |
| 危险操作 | 删除连接 / 清空历史用 `danger` 语义色，今天"取消"按钮反而用了主色（色彩语义反了） |
| 连接表单 | 表单滚动时把「保存 / 测试连接」做成**吸底操作条**（sticky），解决 §1.3-12 |
| 常驻警告 | 状态栏的「密码为降级存储」降级为一个小图标 + tooltip，或改为首次启动时的一次性横幅 |
| 顶栏 Logo | 现在是通用方块图标，换一个有辨识度的字形（如 SQL 括号 + 光标），并统一到品牌色 |
| 状态栏 | 按信息类型分组，用 1px 分隔符 + 状态色点，弱化次要数字 |

### F. 交互与可达性

1. **命令面板（`Cmd/Ctrl+K`）**——Linear/Raycast 式统一入口：执行 SQL、切换连接/库、打开表预览、切换主题、导出。这是本方案里唯一的"新功能级"建议，对日常效率提升最大
2. 结果区快捷键：上一/下一结果集、固定列、复制单元格、全选行
3. 焦点环：现在 `input:focus` 用 `!important` 改 border + box-shadow，会让自定义控件样式跳变；统一成 `*:focus-visible` 一套 outline

## 5. 决策记录（2026-09-17）

| 问题 | 决定 |
|---|---|
| 设计方向 | **A（Linear）为基调 + B（IBM Carbon）的表格规范** |
