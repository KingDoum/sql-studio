# SQL Studio UI 重设计实施规范

> 文档用途：交给后续 AI 或开发人员执行 SQL Studio 的 Renderer UI 重设计。
> 本文档只约束 UI、交互布局、视觉系统和前端组件，不要求修改数据库、IPC、主进程和查询服务。
> 执行原则：先统一设计系统，再重做页面骨架，最后逐个改造组件并进行多尺寸验收。

## 1. 重设计目标

SQL Studio 是给数据分析师长期使用的桌面 SQL 工具，不是营销页面，也不是装饰性 Dashboard。

目标界面必须同时满足：

1. 简约：减少无意义边框、阴影、渐变、玻璃效果和装饰性元素。
2. 圆润：使用适度圆角、柔和控件边界和舒适间距，但不能变成大量胶囊按钮或卡片堆叠。
3. 有美感：颜色、字号、间距、图标、状态色和交互反馈统一，整体有明确设计语言。
4. 高效：连接、Schema、编辑器、执行、结果查看和导出等高频工作流容易发现、容易操作。
5. 可读：SQL、表结构、字段、结果表格必须优先保证清晰度，不能被视觉效果干扰。
6. 一致：所有面板、按钮、输入框、弹窗、菜单和状态提示必须使用同一套设计令牌。
7. 稳定：不同窗口尺寸下不能出现文字溢出、按钮挤压、区域覆盖或布局跳动。

## 2. 当前问题基线

当前 UI 主要问题不在单个组件，而在设计系统失控：

- `theme.css` 约 2386 行，存在多轮追加和后置覆盖规则。
- 同时混用了传统桌面工具、VS Code、玻璃拟态、青色科技风和后台管理风格。
- CSS 中存在渐变、glow、frosted glass、背景微渐变等效果，不适合长时间 SQL 工作。
- `.app-shell`、`.sidebar`、`.modal-panel`、`.tabs-bar` 和按钮存在后置覆盖，维护者难以判断最终样式。
- 左侧连接、Schema 树和右侧编辑器工具栏的信息层级不够清楚。
- 连接行信息过度拥挤，删除操作隐藏在 hover 中。
- 对象浏览器使用字符箭头和 emoji，跨平台视觉不一致。
- App.tsx 同时承担多个工作流，UI 状态和操作入口较为分散。
- 结果区是核心功能，但当前更像编辑器下方的附属区域。

## 3. 设计方向

### 3.1 总体风格

采用“柔和、专业、克制的桌面数据工具”方向：

- 低饱和中性背景。
- 一个主品牌色，配合明确的成功、警告、错误和信息色。
- 细边框，不使用明显发光边缘。
- 4px 间距基线，主要间距使用 8px、12px、16px、20px、24px。
- 默认圆角 6px，输入框和按钮 6px，弹窗 10px，禁止随意使用不同圆角。
- 阴影只用于弹窗、下拉菜单和浮层，不给所有区域加阴影。
- 交互反馈以背景色、边框色和轻微位移为主，不使用闪烁光效。
- 图标统一使用 `lucide-react`，禁止新增 emoji、Unicode 箭头和手绘 SVG 作为功能图标。

### 3.2 推荐色彩系统

最终颜色可微调，但必须遵守角色定义，不得重新引入单一高饱和科技色主导全界面。

```css
  --color-surface-muted: #f8fafc;

  --color-border: #e2e8f0;
  --color-border-strong: #cbd5e1;

  --color-text: #172033;
  --color-text-secondary: #526075;
  --color-text-muted: #8793a5;
  --color-text-disabled: #b8c1ce;

  --color-primary: #3b6fd8;
  --color-primary-hover: #315fc0;
  --color-primary-soft: #eaf2ff;

  --color-success: #23845b;
  --color-success-soft: #eaf8f0;
  --color-warning: #a66a16;
  --color-warning-soft: #fff6df;
  --color-danger: #c74747;
  --color-danger-soft: #fff0f0;
  --color-info: #3574a8;
  --color-info-soft: #edf6ff;

```

如果保留深色主题，必须做成同一套设计令牌的 dark variant，不允许继续沿用当前所有青色 glow 和玻璃效果。深色主题也必须保持清晰边界、低对比噪声和统一圆角。

### 3.3 字体和密度

- UI 默认字号：13px。
- 辅助文字：12px。
- 标签、状态和元信息：11px，但不能低于 11px。
- 面板标题：13px 或 14px，使用中等字重。
- 页面标题：16px，不使用夸张的大标题。
- SQL 编辑器继续使用等宽字体，默认 13px。
- 字母间距保持 0，不使用负 letter-spacing。
- 文字必须通过省略号、换行或响应式布局适配容器，不允许被裁切到不可读。

## 4. 页面信息架构

目标布局：

```text
┌───────────────────────────────────────────────────────────────┐
│ 顶部应用栏：应用名 | 当前连接 | 连接状态 | 常用设置             │
├───────────────┬───────────────────────────────────────────────┤
│               │ SQL 标签栏：标签、脏标记、新建、打开、保存       │
│ 资源侧栏       ├───────────────────────────────────────────────┤
│               │ SQL 工具栏：数据库、执行、停止、格式化、AI       │
│ 连接列表       ├───────────────────────────────────────────────┤
│ Schema 树      │                                               │
│               │ SQL 编辑器                                    │
│               │                                               │
│               ├───────────────────────────────────────────────┤
│               │ 结果工具栏：结果集、行数、耗时、导出、筛选        │
│               ├───────────────────────────────────────────────┤
│               │ 结果表格                                      │
├───────────────┴───────────────────────────────────────────────┤
│ 底部状态栏：连接 | 数据库 | 查询状态 | 耗时 | 行数 | 截断提示      │
└───────────────────────────────────────────────────────────────┘
```

### 4.1 顶部应用栏

目标：提供稳定的全局上下文，不承载过多按钮。

必须包含：

- SQL Studio 品牌标识，使用 Lucide Database 图标和文本。
- 当前连接名称。
- 当前连接状态：未连接、连接中、已连接、连接失败。
- 连接状态使用图标、颜色和文字组合，不能只显示颜色圆点。
- 右侧保留设置入口，使用图标按钮并提供 tooltip。

禁止：

- 顶部放置大量低频按钮。
- 使用大面积渐变背景。
- 使用浮动卡片包裹整条顶部栏。

### 4.2 左侧资源侧栏

左侧是一个连续的资源区域，不做“卡片套卡片”。

结构：

1. 连接区域。
2. 侧栏分隔线。
3. Schema 区域。
4. 必要时显示空状态或错误状态。

建议默认宽度：280px，允许拖拽调整，最小 240px，最大 420px。

连接区域要求：

- 顶部标题“连接”，右侧使用图标按钮新建连接。
- 连接项使用两行布局：第一行名称和状态，第二行主机、端口、数据库摘要。
- 选中项使用浅色背景、左侧 2px 主色标记和清晰文字对比。
- 连接项的编辑、测试、删除放入右侧更多菜单，不用 hover 才显示关键操作。
- 空状态包含图标、简短提示和新建连接按钮。

Schema 区域要求：

- 区域标题包含数据库图标和“对象”或“Schema”。
- 数据库、表、视图、字段使用 Lucide 图标。
- 树层级缩进固定，例如每层 16px。
- 展开/收起使用 `ChevronRight` / `ChevronDown`。
- 表节点的预览、DDL、刷新放入上下文菜单或更多菜单。
- 字段名称、类型和注释采用稳定的列对齐，不使用 emoji 作为信息标记。
- 字段双击插入编辑器的能力保留，但通过 tooltip 和 hover 背景反馈提示。

### 4.3 SQL 标签栏

- 标签栏高度稳定，建议 36px。
- 标签内容包含文件名或未命名标题、脏标记和关闭按钮。
- 当前标签使用底部 2px 主色线或浅色背景，不使用大面积发光。
- 新建、打开、保存、另存为使用图标按钮，提供 tooltip。
- 标签过多时横向滚动，不允许压缩到文字无法识别。
- 关闭脏标签必须保留确认流程。

### 4.4 SQL 工具栏

工具栏按使用频率排序：

1. 当前数据库选择。
2. 执行。
3. 停止。
4. 格式化。
5. AI 补全状态/设置。
6. 其他低频动作。

要求：

- 执行按钮是唯一主要强调按钮。
- 停止按钮使用 danger 角色，但仅在查询执行中显示或启用。
- 工具栏按钮高度统一，图标和文字垂直居中。
- 低频按钮放入更多菜单，避免横向拥挤。
- 快捷键继续工作，按钮 tooltip 中可显示快捷键，但不在页面上增加大段说明文字。

### 4.5 SQL 编辑器

- 编辑器区域必须拥有稳定的最小高度。
- 编辑器背景和周边工具栏有清晰边界。
- 不在编辑器外层增加厚重卡片边框。
- 当前主题、字体和字号由 SettingsPanel 控制，但必须通过统一 CSS 变量传递。
- 编辑器加载中、无连接、无标签和错误状态要分别设计，不能只显示一行普通文本。
- Monaco 自身的高亮、补全和光标可见性优先于装饰效果。

### 4.6 结果工作区

结果区是核心一级功能，不能设计成普通附属卡片。

必须包含：

- 结果集标签。
- 当前结果集的行数、耗时、是否截断。
- 导出入口。
- 筛选入口。
- 可调整高度的上边界拖拽条。
- 空结果、查询错误、加载中和截断状态。

结果表格要求：

- 表头固定。
- 表头、筛选行和数据行使用同一列宽来源。
- 行高稳定，不因内容变化导致布局跳动。
- hover 只改变背景，不使用强发光。
- NULL、二进制、长文本使用明确的视觉标记和 tooltip。
- 列宽拖拽必须有清晰的 cursor 和 1px 反馈线。
- 大量数据继续使用虚拟滚动。

### 4.7 底部状态栏

状态栏高度建议 24px 至 28px，承载低干扰的实时信息：

- 当前连接。
- 当前数据库。
- 查询状态。
- 查询耗时。
- 返回/影响行数。
- 截断警告。

状态栏不能成为第二个工具栏，不放置大量按钮。

## 5. 组件逐项改造清单

### 5.1 `App.tsx`

改造目标：只保留页面骨架和工作流组合，不继续堆积所有 UI 状态和业务细节。

要求：

- 重建顶部应用栏、资源侧栏、主工作区和底部状态栏布局。
- 连接上下文集中展示，避免当前连接信息散落。
- 保留现有查询、保存、收藏、历史、预览和设置行为。
- 将脚本、查询、收藏和设置相关 UI 编排逐步提取为 hooks 或工作流组件。
- 不修改现有 IPC channel 名称和数据契约。
- 不把业务逻辑搬进 CSS 或组件样式判断。

验收：

- 无标签、无连接、无结果、执行中、执行失败和执行成功状态均可正常显示。
- 主要操作入口在 1440px、1280px 和较窄窗口下均可发现且不重叠。
- 现有 App 组件测试继续通过，必要时补充布局状态测试。

### 5.2 `theme.css` / `index.css`

改造目标：清理现有重复覆盖，建立唯一设计令牌和按组件分组的样式结构。

要求：

- 删除或停用 frosted glass、accent glow、border glow、hover glow 和背景微渐变。
- 删除重复 selector 的后置补丁，确保同一组件的主要规则集中出现。
- 建立颜色、字号、间距、圆角、边框、阴影和 transition 变量。
- 统一按钮、输入框、select、菜单、弹窗、状态和 tooltip 样式。
- 统一 hover、active、focus-visible、disabled、loading 和 error 状态。
- 保留 dark theme 时，使用同一变量体系覆盖，不复制一套混乱规则。

验收：

- 关键 selector 没有多处互相覆盖的最终样式。
- 全局扫描不应出现新的渐变、glow、backdrop-filter 或大面积透明玻璃效果。
- 所有可交互元素都有 hover、focus-visible、disabled 状态。
- 颜色角色可解释，不能出现“同一种青色到处代表不同语义”。

### 5.3 `ConnectionManager.tsx` / `ConnectionForm.tsx`

改造目标：让连接管理清晰、稳定、容易扫描。

要求：

- 连接列表改为两行信息布局。
- 使用 Lucide Server、Database、MoreHorizontal、Plug、Trash2、Pencil 等图标。
- 新建连接按钮使用图标加 tooltip，表单提交按钮可以使用“保存”文字和图标。
- 测试中状态要有明确文字和 loading 图标。
- 删除和编辑不依赖 hover 才能发现。
- 表单字段分组：基本信息、认证信息、连接选项。
- 表单错误直接显示在字段附近，不只在顶部显示一段红字。
- 密码字段保留当前安全边界，不改变 IPC 输入结构。

验收：

- 连接名称、主机、端口和数据库在 280px 侧栏宽度下可读。
- 新建、编辑、测试、删除工作流保持可用。
- 测试中、成功、失败和未测试状态视觉明确。
- 表单在窄窗口下不出现横向溢出。

### 5.4 `ObjectExplorer.tsx`

改造目标：把对象树做成专业数据库资源浏览器。

要求：

- 删除 emoji、Unicode 箭头和不统一的文本图标。
- 使用 Lucide Database、Table2、Eye、KeyRound、ChevronRight、ChevronDown、RefreshCw、MoreHorizontal。
- 数据库、表、视图、字段使用稳定的缩进和层级颜色。
- 预览、DDL、刷新通过图标按钮或上下文菜单提供。
- 加载状态使用小型 spinner 或 Skeleton，不使用大量文字占位。
- 错误状态提供重试按钮。
- 保留懒加载、请求令牌和双击打开/插入行为。

验收：

- 数据库、表、视图和字段可快速区分。
- 展开/收起状态清楚，连续点击不会产生跳动。
- 切换连接时旧连接请求不会覆盖新连接内容。
- 长名称使用省略号，hover tooltip 显示完整名称。
- 右键菜单或更多菜单点击后能正确关闭，不遮挡主要内容。

### 5.5 `EditorTabs.tsx`

改造目标：实现紧凑但舒适的文件标签体验。

要求：

- 统一标签高度、内边距和关闭按钮尺寸。
- 活动标签使用背景和底部线，不使用发光。
- 脏标记使用小圆点或明确状态图标。
- 新建、打开、保存和另存为按高频顺序排列。
- 标签过多时横向滚动，并保持当前标签可见。

验收：

- 新建、切换、关闭、脏状态和关闭确认均不回归。
- 文件名过长时不撑破标签布局。
- 关闭按钮可点击区域足够，且不会误触标签切换。

### 5.6 `SqlEditor.tsx`

改造目标：让编辑器成为视觉中心，但保持克制。

要求：

- 重做 SQL 工具栏层级。
- 执行按钮、停止按钮、格式化、AI 设置和数据库选择使用统一控件尺寸。
- 执行中状态必须明显，但不能闪烁或占用额外布局空间。
- 保留 Monaco 本地加载、补全、语义高亮、格式化、快捷键和 AI 行内补全。
- 主题和字号变化不能导致编辑器容器跳动。

验收：

- 首次打开、切换标签和执行 SQL 时编辑器不会明显闪烁或重复挂载。
- 执行、停止、格式化、AI 设置入口可用。
- Monaco 补全和快捷键没有因视觉重构失效。

### 5.7 `ResultTabs.tsx` / `ResultGrid.tsx`

改造目标：让查询结果具备专业数据表格的可读性。

要求：

- 结果区高度可调整，最小高度固定。
- 结果集标签和状态信息分层显示。
- 结果表头、筛选区和表体共享同一列宽配置。
- 空结果、加载、错误、截断和成功状态分别设计。
- 保留虚拟滚动、排序、筛选、复制、二进制和 NULL 格式化。
- 导出动作放在结果工具栏，不占用每行空间。

验收：

- 0 行、1 行、长文本、多列、超长列名和 50,000 行场景均不破坏布局。
- 表头与筛选输入不会错位。
- 滚动、排序、筛选和复制功能不回归。
- 截断提示同时出现在结果工具栏或状态栏中，且不会遮挡数据。

### 5.8 `ExportMenu.tsx`

改造目标：降低导出操作的认知成本。

要求：

- 导出按钮使用 Download 图标和明确 tooltip。
- 菜单项包含文件类型图标、名称和必要的简短描述。
- 菜单宽度稳定，不因提示文字变化而跳动。
- 禁用状态和导出中状态明确。
- 保存对话框、导出成功和定位文件行为保持不变。

验收：

- Excel、CSV、SQL INSERT 三种导出均可触发。
- 无结果时导出按钮禁用或给出明确提示。
- 导出失败时错误反馈可读，不静默失败。

### 5.9 `HistoryPanel.tsx` / `FavoritesPanel.tsx`

改造目标：让历史和收藏成为可扫描的工具面板，而不是堆叠列表。

要求：

- 历史和收藏使用统一的弹窗/侧滑面板结构。
- 顶部有标题、搜索框、数量和关闭按钮。
- 列表项使用稳定的主信息、辅助信息和操作区域。
- SQL 预览限制行数，完整内容通过 tooltip 或打开操作查看。
- 回填、打开、重命名、删除使用 Lucide 图标，并提供 tooltip。
- 删除使用明确确认流程。

验收：

- 搜索、回填、打开、删除、收藏、重命名均可用。
- 空列表、加载中、错误和无搜索结果均有明确状态。
- 列表项不会因 SQL 长度变化而抖动。

### 5.10 `SettingsPanel.tsx` / `AiSettingsPanel.tsx` / `DataPreviewModal.tsx`

改造目标：统一所有弹窗和设置面板的视觉结构。

要求：

- 统一弹窗宽度、圆角、标题栏、关闭按钮、内容间距和底部操作区。
- 弹窗遮罩使用低透明度纯色，不使用背景模糊和强渐变。
- 设置按 section 分组，使用清晰的分组标题和辅助说明。
- 主操作按钮统一放在右下角或固定底部操作区。
- 数据预览弹窗使用结果表格规范，不再单独产生一套表格风格。
- AI Key 输入保持密码类型和安全存储逻辑，不在 UI 或日志显示明文。

验收：

- 表单错误和保存失败有明确反馈。

## 6. 交互状态规范

所有组件必须明确设计以下状态：

| 状态 | 要求 |
|---|---|
| Default | 正常背景、边框和文本 |
| Hover | 背景轻微变化，不能发光 |
| Active/Selected | 使用主色软背景或底部线，不能只靠颜色圆点 |
| Focus-visible | 2px 清晰焦点环，支持键盘操作 |
| Disabled | 降低对比度并禁止点击 |
| Loading | 使用稳定尺寸的 spinner 或 skeleton，不能导致布局跳动 |
| Error | 使用 danger 色、图标和可读错误文本 |
| Empty | 图标、短提示和主要操作 |
| Success | 使用 success 色和短反馈，避免长时间遮挡内容 |

## 7. 响应式与尺寸验收

虽然这是桌面应用，但必须覆盖以下窗口尺寸：

| 尺寸 | 重点检查 |
|---|---|
| 1440 × 900 | 完整工作台主场景 |
| 1280 × 800 | 常用桌面尺寸，检查工具栏拥挤 |
| 1024 × 700 | 项目设置的最小窗口，检查侧栏和结果区 |
| 900 × 700 | 窄窗口降级，检查横向溢出和弹窗 |

验收条件：

- 页面没有横向滚动条，除明确需要横向滚动的标签栏和结果表格外。
- 左侧资源面板不会覆盖主编辑器。
- 工具栏按钮、文字和图标不互相遮挡。
- 弹窗不会超出窗口可视范围。
- 侧栏、编辑器和结果区的最小尺寸明确，不能因内容变化而缩小到不可用。
- 长连接名、长表名、长字段名、长 SQL、长错误信息都能通过省略号、换行或滚动处理。

## 8. 可访问性验收

- 所有图标按钮必须有 `title` 或等价 tooltip。
- 所有输入框必须有可识别 label 或 aria-label。
- 键盘可以访问关闭、保存、执行、停止、搜索和确认操作。
- `focus-visible` 状态可见，不能用 `outline: none` 后不补焦点样式。
- 颜色不是唯一状态表达方式，成功、错误、连接状态必须同时有文字或图标。
- 不能使用过小的点击区域；图标按钮建议最小 28px × 28px。
