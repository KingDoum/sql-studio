## 1. 目标与非目标

### 1.1 目标

1. 修复已确认的收藏定位、SQL 导出标识符、写操作识别和文件路径风险。
2. 保持 Main、Preload、Renderer 分层和现有 IPC 契约稳定。
3. 提高服务依赖注入、查询耗时、取消和资源释放行为的可验证性。
4. 补齐 Windows Electron、真实 MySQL/MariaDB 和打包产物验收。
5. 让每项完成结论都具备代码、测试、命令输出或真实环境证据。

### 1.2 非目标

- 不重新进行已经完成的 S1-S5 UI 大改版。
- 不在同一阶段同时进行连接池替换、IPC 大拆分和 SQL 解析重写。
- 不以修改文档文字代替代码和测试验证。
- 不删除用户数据目录来规避原生模块或运行时问题。

## 3. 风险分级

### P0：发布阻断

- SQL 写操作可能被错误放行。
- 文件路径可能越界或错误覆盖文件。
- 生成的 SQL INSERT 不能可靠执行。
- 真实 Electron 启动、连接和核心查询流程未验证。

### P1：必须处理

- 收藏读、删、重命名定位不一致。
- 查询取消、连接释放、历史写入语义不清。
- IPC handler 重复创建服务，导致状态或生命周期不可控。
- 文档把规划功能或历史结果描述为当前已完成。

### P2：后续优化

- 统一普通查询为连接池执行。
- 拆分 `App.tsx` 和 `ipc.ts`。
- 结果区高度持久化。
- 面板字号变量与实际 UI 完整联动。

## 4. 阶段任务

### S0：基线确认

目标：确认工作区、源码、文档和验证命令一致。

必须做：检查 `git status`、提交记录、Node/npm/Electron 版本；执行 `npm run typecheck`、`npm test`、`npm run build`；统计实际测试文件和用例；确认 `.bak` 文件是否被跟踪或进入产物；确认 UI 变更边界。

通过条件：三条基础命令成功；失败项有完整错误和环境判断；没有覆盖用户已有改动。

### S1：收藏定位统一

目标：保存、读取、删除、重命名使用同一套安全定位规则。

涉及：`src/main/services/favorites-store.ts`、`tests/main/favorites-store.test.ts`，必要时 `src/main/ipc.ts`。

必须覆盖：重名、非法字符、路径分隔符、空名称、超长名称、旧格式、相似名称误匹配、中断后无半成品。

通过条件：所有收藏工作流回归通过，非法名称不能越出收藏目录，旧数据有兼容或迁移结论。

回退：保留旧格式读取，不做批量迁移；新逻辑失败时不得删除原文件。

### S2：SQL 导出与标识符安全

目标：生成的 INSERT 对特殊表名、列名和值都安全且可执行。

涉及：`src/main/services/sql-exporter.ts`、CSV 导出相关测试。

必须覆盖：反引号标识符、database.table 输入策略、NULL、数字、布尔、二进制、单引号、反斜杠、换行、回车、NUL、batchSize 非法值，以及 CSV BOM、RFC 4180、公式注入和 backpressure。

通过条件：单元测试通过，并用真实 MySQL/MariaDB 冒烟执行至少一份包含特殊字符的 INSERT。

回退：保留旧导出入口；若格式策略不明确，停止扩大范围，先补契约和测试。

### S3：SQL 写操作识别与安全确认

目标：Renderer 提示和 Main 实际安全策略一致，无法判断时按高风险处理。

涉及：`src/renderer/lib/sql-utils.ts`、`src/main/services/query-service.ts`、相关共享类型和测试。

必须覆盖：INSERT、UPDATE、DELETE、REPLACE、ALTER、DROP、TRUNCATE、CTE 写操作、CALL、多语句读写混合、注释、字符串、括号、大小写和前置空白。

通过条件：纯读不误报；高风险不放行；不确定语句有明确错误或确认策略；Renderer 判断不能成为唯一安全边界。

回退：不采用“无法识别就放行”；复杂方言先归为高风险并记录限制。

### S4：服务依赖注入与 IPC 组织

目标：服务实例创建、使用、关闭顺序明确，行为不因拆分改变。

涉及：`src/main/index.ts`、`src/main/ipc.ts`、`src/main/services/*`、Main/Shared 测试。

必须做：统一服务实例创建位置；检查 handler 是否重复 `new`；明确生命周期和退出顺序；保持 channel 名称和数据契约不变。

通过条件：IPC、生命周期、取消和服务注入测试通过；无重复 handler 注册；Renderer 边界不变。

回退：如果需要改变 IPC 契约，暂停本阶段并拆出兼容性设计。

### S5：查询耗时、取消和资源释放

目标：明确单结果集耗时、总耗时、取消、历史和连接释放语义。

涉及：`query-service.ts`、`connection-manager.ts`、`ipc.ts` 和相关测试。

必须做：先记录当前临时连接行为；验证单语句、多语句、并发、取消前后、失败释放、截断和历史写入；单独评估是否值得连接池化。

通过条件：取消后不会继续写入错误历史；连接一定释放；`elapsedMs` 语义有实现和测试；真实 MySQL 至少完成一次取消冒烟。

回退：连接池替换不得与本阶段其他重构混做；若兼容性不足，保留临时连接并记录原因。

### S6：系统文件对话框与路径边界

目标：打开、保存、另存为、导出具备可取消、可覆盖确认和跨 Windows 路径处理能力。

通过条件：Windows GUI 验证打开、保存、另存为、导出、取消、覆盖、无权限、占用文件、非 ASCII 文件名和 UNC/盘符路径。

回退：系统对话框改造出现回归时，保留原入口但不得扩大路径访问权限；不得静默覆盖文件。

### S7：真实环境与发布验收

目标：证明项目可以在目标 Windows Electron 环境和测试 MySQL 环境运行。

必须做：执行完整 E2E 旅程、打包启动、ABI 检查、离线 Monaco 检查、日志脱敏检查，并记录版本、日期、命令、结果和截图。

发布门槛：typecheck、全量测试、build、Windows Electron 冒烟、MySQL 冒烟、关键导出、路径取消流程全部通过；所有 P0/P1 风险已解决或有明确阻断说明。

## 5. 统一执行规则

每个阶段都必须遵循：读取源码和现有测试 → 检查 git 状态 → 小范围修改 → 运行相关测试 → 汇报结果 → 决策门通过后再扩大范围 → 全量验证 → 更新文档。

每个阶段报告必须包含：修改文件、行为变化、测试命令、实际输出摘要、已知限制、回退方式、是否需要下一阶段确认。
