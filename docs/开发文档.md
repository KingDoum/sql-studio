## 3. 构建体系

### 3.1 三类产物

| 部分 | 入口 | 构建配置 | 产物 |
|---|---|---|---|
| Main | `src/main/index.ts` | `vite.main.config.ts` | `dist/main/main.cjs` |
| Preload | `src/preload/index.ts` | `vite.main.config.ts` | `dist/main/preload.cjs` |
| Renderer | `src/renderer/main.tsx` | `vite.config.ts` | `dist/renderer/` |

`package.json` 为 ESM 项目，但 Electron 主进程和 preload 使用 CommonJS 产物，因此不要把 `.cjs` 改回 `.js`。`src/main/index.ts` 中 preload 路径必须对应 `preload.cjs`。

主进程构建会把 npm 包和 Node 内置模块 external 化。better-sqlite3 是原生模块，不能被打进 bundle。

### 3.2 别名约束

以下三处必须保持同步：

- `tsconfig.json`
- `vitest.config.ts`
- `vite.config.ts`

当前别名：

```text
@/*          -> src/*
@shared/*    -> src/shared/*
@main/*      -> src/main/*
@preload/*   -> src/preload/*
@renderer/*  -> src/renderer/*
```

修改别名后必须同时运行 typecheck、测试和 Renderer 构建。

### 3.3 Monaco

Monaco 通过 npm 包本地加载，生产环境不能依赖 CDN。`src/renderer/main.tsx` 负责 loader 预热和本地 Monaco 配置；CSP、worker 和 `monaco-editor` 依赖必须一起维护。

## 4. 代码边界

### 4.1 Renderer

Renderer 只负责 UI、交互状态和纯逻辑：

- 不 import mysql2、better-sqlite3 或 Node 文件模块。
- 不读取密码、不保存解密后的连接配置。
- 不直接使用 `ipcRenderer`。
- 所有主进程能力通过 `window.sqlStudio['domain:action']()` 调用。

### 4.2 Preload

Preload 只做两件事：

1. 根据 `IPC_CHANNELS` 构造类型化 API。
2. 调用 `ipcRenderer.invoke()` 并解包统一响应。

不要在 preload 增加业务判断、数据库逻辑或文件操作。

### 4.3 Main

Main 负责：

- Electron 生命周期。
- IPC handler 注册。
- 主进程服务组装。
- 数据库连接和查询。
- SQLite 和本地文件访问。
- safeStorage 加解密。
- AI API 调用。

### 4.4 Service

服务应尽量通过构造函数注入依赖：

- 数据库工厂。
- 文件系统抽象。
- 加密函数。
- 外部 fetch。
- SQLite 路径。

这样可以在 Vitest 中使用 mock，不依赖真实 Electron 或真实 MySQL。

## 5. IPC 开发流程

新增或修改 IPC 时按以下顺序执行：

1. 在 `src/shared/types.ts` 增加或调整共享数据类型。
2. 在 `src/shared/ipc-contract.ts` 登记 channel、请求映射和响应映射。
3. 在 `src/main/ipc.ts` 实现 handler。
4. 必要时在 `src/main/index.ts` 注入服务实例。
5. 确认 preload 自动暴露该 channel，或同步调整 preload 类型。
6. 在 Renderer 调用 `window.sqlStudio`。
7. 增加主进程、渲染进程或契约测试。
8. 运行 typecheck、相关测试和完整构建。

统一响应模型：

```text
Main handler 成功 -> { ok: true, data }
Main handler 失败 -> { ok: false, error, errorType? }
Preload 成功      -> Promise<data>
Preload 失败      -> rejected Error
```

channel 命名统一使用 `域:动作`，例如 `query:execute`、`favorites:list`。

## 6. 数据库与查询开发

### 6.1 连接安全

`ConnectionConfig` 只能在 Main 内部使用，包含解密后的密码；`ConnectionSummary` 可以返回 Renderer，但不得包含 password。

连接密码流程：

```text
Renderer ConnectionInput
  -> IPC
  -> Security.encrypt
  -> SQLite connections.password

SQLite 密文
  -> Security.decrypt
  -> Main ConnectionManager
  -> mysql2
```

编辑连接时 password 为空表示保留旧密码。新增连接时必须明确处理空密码策略。

### 6.2 Schema 查询

SchemaCache 对每个 connectionId 单独建立缓存，缓存数据库、表、字段和 DDL。所有库名、表名都必须经过反引号转义：

```ts
name.replace(/`/g, '``')
```

Schema 变更、连接配置修改或连接删除后要清理对应缓存，避免旧连接结果污染新连接。

### 6.3 查询执行

查询流程由 `query:execute`、`ConnectionManager.executeMany()` 和 `QueryService.run()` 组成：

- `executeMany()` 负责 MySQL 多语句连接和原始结果归一化。
- `QueryService` 负责列、行、截断、写操作标记和聚合耗时。
- 默认单结果集最大 50,000 行。
- 历史记录在 IPC 查询 handler 中自动写入。

当前实现的关键限制：普通 `query:execute` 通过 `executeMany()` 使用临时多语句连接，不是稳定的连接池查询（这是既有设计，后续如需统一为池查询需另做兼容与测试）。查询取消链路已贯通：`makeExecutor()` 把 signal 透传给 `executeMany()`，abort 时销毁临时连接中止查询。

不要在没有测试的情况下修改多语句解析、结果集类型或取消机制。

### 6.4 写操作判断

Renderer 当前会先识别写操作并弹确认，但该判断不能作为数据库安全边界。后续应覆盖：

- INSERT、UPDATE、DELETE、REPLACE、ALTER、DROP、TRUNCATE。
- CTE 包裹写操作。
- 存储过程调用。
- 多语句混合读写。
- 注释、字符串和括号干扰。

## 7. 文件与导出开发

### 7.1 ScriptStore

`ScriptStore` 负责用户自选路径下的 SQL 文件读写。对话框由 IPC 主进程 handler 调用，Store 只负责文件 IO。

### 7.2 FavoritesStore

收藏目录为 Electron `userData/queries/`。每条收藏是一个 `.sql` 文件，文件头保存：

```sql
-- name: 每日统计
-- connection: conn_xxx
-- tags: 日报, 活跃
-- createdAt: 2026-08-20T10:00:00.000Z

SELECT ...;
```

文件名必须经过安全化，不能允许路径分隔符和系统保留字符。重名时追加 ` (2)`、` (3)`。

读取、删除、重命名应使用一致的收藏定位规则。当前 `readFavorite()` 与删除/重命名的回扫逻辑不完全一致，修改时要补齐测试。

### 7.3 CSV

CSV 导出要求：

- UTF-8 BOM。
- RFC 4180 字段转义。
- 逗号、引号、换行正确包裹。
- 以 `= + - @` 开头的字段增加前缀，避免 Excel 公式注入。
- WritableStream 返回 false 时等待 drain，不能无视 backpressure。

### 7.4 SQL INSERT

SQL 导出必须：

- 正确处理 NULL、数字、布尔值和二进制。
- 字符串转义单引号、反斜杠、换行、回车和 NUL。
- 表名和列名使用统一标识符转义。
- 校验 batchSize，避免 0 或负数导致死循环。

当前实现尚未完全转义表名和列名，属于待修复风险。

## 9. 调试与排错

### 9.1 Electron 启动失败

依次检查：

1. `npm run typecheck`。
2. `npm run build:main`。
3. `dist/main/main.cjs` 和 `dist/main/preload.cjs` 是否存在。
4. preload 路径是否使用 `.cjs`。
5. 开发模式 Vite 是否监听 5173。
6. `VITE_DEV_SERVER_URL` 是否正确。

### 9.2 IPC 无 handler

检查：

1. channel 是否在 `IPC_CHANNELS` 登记。
2. 请求/响应 map 是否登记。
3. `registerIpc()` 是否在 `app.whenReady()` 中调用。
4. handler 是否被重复注册。
5. preload 是否读取同一份 `IPC_CHANNELS`。
6. IPC 测试是否覆盖 channel。

### 9.3 better-sqlite3 加载失败

典型错误：

```text
was compiled against a different Node.js version
Module did not self-register
```

原因是 Node ABI、Electron ABI 或现有 `.node` 文件不匹配。优先运行：

```bash
npm run rebuild
```

并在修改 better-sqlite3、Electron 或 Node 版本后重新验证。测试中的 `store.close()` 二次报错通常是构造函数已经因原生模块加载失败，不能把它当成根因。

### 9.4 查询取消无效

检查完整链路：

```text
App clientQueryId
  -> query:execute
  -> queryAborters Map
  -> QueryService signal
  -> makeExecutor(signal)
  -> ConnectionManager.executeMany(signal)
  -> mysql connection destroy
```

任何一层不传 signal，停止按钮都可能只改变 UI 状态而不能中断数据库查询。

## 10. 维护规则

1. 不在 `src/main`、`src/preload`、`src/renderer` 重复定义共享类型。
2. 不在 Renderer 直接访问 Node 或数据库。
3. 不把密码、API Key、完整敏感 SQL 写入日志。
4. 不把 `.bak` 文件当作正式源码引用。
5. 不用历史文档中的测试数量替代实际命令输出。
6. 新增功能必须同时补测试。
7. 数据库、文件、加密、连接池变更先做小范围验证，再进行全量验证。
8. 修改前检查 `git status` 和 `git diff`，不覆盖用户已有改动。
9. 不通过重装依赖或清理目录解决问题而不记录原因。
10. 文档更新必须反映实际代码，不得把规划功能写成已完成。
