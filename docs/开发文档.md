## §3 构建体系（已踩通的路径，别改）

### §3.1 三进程产物

| 进程 | 入口 | 构建方式 | 产物 | 格式 |
|---|---|---|---|---|
| 主进程 | `src/main/index.ts` | `vite build --config vite.main.config.ts` | `dist/main/main.cjs` | CJS |
| preload | `src/preload/index.ts` | 同上（双入口） | `dist/main/preload.cjs` | CJS |
| 渲染进程 | `src/renderer/main.tsx` | `vite build`（vite.config.ts） | `dist/renderer/` | ESM |

### §3.2 关键决策（改动前必读）

1. **`package.json` 声明了 `"type": "module"`**，但 Electron 主进程/预加载必须是 CommonJS
   → 主进程/preload 产物固定输出 `.cjs` 扩展名（`vite.main.config.ts` 的 `entryFileNames: '[name].cjs'`）。
   → **新增主进程入口文件时，引用 `__dirname` 等 CJS 变量的写法保持现状**。

2. **主进程构建 external 全部 npm 包 + node 内置模块**（`vite.main.config.ts` 的 external 函数）
   → 原生模块（better-sqlite3）**绝不能被打进 bundle**，否则运行时加载报错。

3. **渲染进程 dev server 端口固定 5173**，主进程通过 `VITE_DEV_SERVER_URL` 环境变量加载（`npm run dev` 里 cross-env 注入）。

4. **`src/main/index.ts` 里 preload 路径**是 `path.join(__dirname, 'preload.cjs')`（.cjs 不是 .js）。

5. **别名三处必须同步**：`tsconfig.json paths` / `vitest.config.ts alias` / `vite.config.ts resolve.alias`，缺一即 dev/test/build 三态不一致。

### §3.3 vitest 双环境

- `vitest.config.ts` 默认 `environment: 'node'`（主进程服务单测）。
- **渲染进程组件测试**在文件第一行写注释切换：
  ```ts
  // @vitest-environment jsdom
  ```
- 路径别名：`@/*` → `src/*`，`@renderer/*` → `src/renderer/*`，`@shared/*` → `src/shared/*`，`@main/*` → `src/main/*`，`@preload/*` → `src/preload/*`。

## §4 代码约定（违反会被架构文档 R5/R6/R8 追责）

### §4.1 类型唯一来源

- 跨进程类型 → 只写 `src/shared/types.ts`。
- IPC channel 常量 + 请求/响应类型 → 只写 `src/shared/ipc-contract.ts`。
- 禁止在 main/preload/renderer 内复制定义同名字段类型（如各自定义 `ConnectionSummary`）。

### §4.2 IPC 约定

- channel 一律以 `域:动作` 命名（如 `app:ping`、`connections:list`、`query:execute`）。
- 主进程 `ipcMain.handle` 的返回值统一包装：成功直接返回值；失败抛 `Error`，由路由层转 `{ ok:false, error }`。
- preload 只做 `ipcRenderer.invoke` 的类型化透传，不写业务逻辑。
- 渲染进程通过 `window.sqlStudio['channel:name']()` 调用（channel 带冒号，用方括号索引）。

### §4.3 服务层可测试性

- 每个服务构造函数**依赖注入**（连接工厂 / 存储实例 / 加密函数 / sqlite 路径），禁止内部直接 `require('electron')` 或 `new mysql2`。
- 例：`MetadataStore({ security, dbPath, createDb })`；`ConnectionManager({ mysqlFactory, config })`。

### §4.4 安全红线

- 密码字段：只在主进程内存/密文落库，**任何 IPC 返回渲染进程的连接对象都不含 password**（用 `ConnectionSummary`）。
- 日志（electron-log）：只记 SQL 摘要、行数、耗时；不落密码与完整 SQL。
- API Key：经 `security.encrypt()` 加密后存储，读取时 `security.decrypt()` 解密。

- `*.test.tsx` — 组件 / jsdom 环境（文件头加 `// @vitest-environment jsdom`）

### §5.3 mock 模式

**主进程单测**：mock 依赖注入，不连真实 MySQL。
```ts
const mockMysqlFactory = vi.fn(() => ({ getConnection: vi.fn() }));
const cm = new ConnectionManager({ mysqlFactory: mockMysqlFactory });
```

**组件单测**：mock `window.sqlStudio`，提供假的 IPC 返回值。
```ts
(window as unknown as { sqlStudio: unknown }).sqlStudio = {
  'connections:list': vi.fn(async () => [mockConnection]),
  'schema:databases': vi.fn(async () => ['test_db']),
};
```

### §5.4 常见测试陷阱

| 陷阱 | 表现 | 修复 |

## §7 坑位与经验记录（踩过即记，维护阶段必更新）

> 格式：`[日期] 问题 → 原因 → 解决办法`。按时间倒序。

### 会话8 坑位（体验优化专项）

- `[2026-08-20 会话8]` **Electron 中 `window.prompt` 返回 null → 导出静默失败**
  → 渲染进程 `window.prompt` 在 Electron（contextIsolation）下基本残废，`if (!filePath) return` 直接吞掉。
  → 改走 IPC + 主进程 `dialog.showSaveDialog`（新通道 `dialog:showSaveDialog`），`defaultPath` 用 settings 记忆的上次导出目录。
- `[2026-08-20 会话8]` **Electron dialog 需在主进程调用，测试环境顶层 import electron 会炸**
  → `import { dialog } from 'electron'` 在 vitest node 环境 require 返回字符串（非 Electron 运行时无 dialog）。
  → handler 内动态 `require('electron')`，测试只断言通道已注册，不调用真实对话框。
- `[2026-08-20 会话8]` **默认执行库取 `databases[0]` 可能是 `information_schema`（系统库）**
  → `SHOW DATABASES` 首行通常是系统库，无默认库时执行 `SELECT * FROM users` 报「找不到表」。
  → 选库跳过 `SYSTEM_DATABASES`（information_schema/mysql/performance_schema/sys），执行时再加兜底链：snapshot 默认库 → 连接配置默认库 → 第一个用户库。
- `[2026-08-20 会话8]` **`key={tab.id}` 强制 Monaco 重挂载 → 切标签/新建时 1-3s 无法输入**
  → key 变化触发 editor 销毁重建（tokenizer 重跑 + 丢撤销历史）。
  → 去掉 key，`<Editor path={tab.id} defaultValue={tab.sql}>` 单实例多 model（对齐 react-monaco-editor #269 官方方案），`main.tsx` 预热 `loader.init()`。
- `[2026-08-20 会话8]` **补全不支持表别名：`FROM users u WHERE u.` 无联想**
  → `endWithQualifiedDot` 只匹配精确表名 `users.`，别名 `u.` 查无此表。
  → 新增 `extractTableAliases(prefix)` 解析 FROM/JOIN/INTO/UPDATE/TABLE 段的 `表 [AS] 别名`，`别名.` 映射回表名取字段。
- `[2026-08-20 会话8]` **结果表筛选行与表头错位**
  → 表头宽 `COL_W=150`（border-box），筛选 input 宽 `COL_W-16`+padding，两处各自算宽。
  → 改为表头/筛选/表体共用同一 `gridTemplateColumns`（单一列宽源），根治错位。
- `[2026-08-20 会话8]` **jsdom 无 `setPointerCapture` → 拖拽测试抛 TypeError**
  → jsdom 未实现 PointerEvent capture API。
  → `setPointerCapture?.()` 可选调用，测试降级为断言 resize handle 存在（真实拖拽在 Electron 验证）。
- `[2026-08-20 会话8]` **forwardRef 组件的 ref 是第二参数，不是 props 字段**
  → `function({...}: Props, ref)` 解构到 props 会 TS 报错 `Property 'ref' does not exist`。
  → forwardRef 回调签名固定为 `(props, ref)` 两参。

### 会话7 坑位（构建发布阶段）

- `[2026-08-20 会话7]` **preload 构建 external 误吞 @ 别名 → window.sqlStudio undefined**
  → `vite.main.config.ts` external 函数只对 `.`/`/`/盘符 开头返回 false，`@shared/ipc-contract` 被当外部包，preload 运行时 `require("@shared/...")` 失败。
  → external 判定加 `id.startsWith('@')` + 补 `resolve.alias`（@shared/@main/@preload）。
- `[2026-08-20 会话7]` **主进程入口从未调用 registerIpc() → no handler registered**
  → `src/main/index.ts` 只注册了 `app:ping`，其余 26 个业务 handler 未注册。
  → 在 `app.whenReady()` 中初始化全部服务（Security/MetadataStore/ConnectionManager/FavoritesStore）后调用 `registerIpc(deps, ipcMain)`。
- `[2026-08-20 会话7]` **Monaco 生产构建从 CDN 加载被 CSP 拦截**
  → `@monaco-editor/react` 默认从 jsDelivr 拉 Monaco，CSP `script-src 'self'` 拦截 → 编辑器永远"加载中"。
  → `main.tsx` 加 `loader.config({ monaco })` 本地加载；`package.json` 加 `monaco-editor` 依赖；CSP 加 `'unsafe-eval'` + `worker-src 'self' blob:`。
- `[2026-08-20 会话7]` **测试连接失败显示"连接成功"（返回值被丢弃）**
  → `testConnection` 返回 `{ok:false, message}` 经 IPC 包装后 resolve 正常值，`handleTest` 直接 `await` 不检查 → UI 永远显示成功。
  → `const res = await ...; if (!res.ok) throw new Error(res.message);`
- `[2026-08-20 会话7]` **查询历史双重记录 + success 恒为 true**
  → `ipc.ts` query:execute handler 已自动 addHistory，同时 `App.tsx` handleExecute 又发一次 `history:add` → 每条执行两条记录；`!result.resultSets.some(r => r.truncated) || true` 恒为 true。
  → 删除 App 端调用；`success: result.resultSets.every(r => !r.truncated)`。
- `[2026-08-20 会话7]` **SchemaCache 每次 IPC 新建实例 → 缓存完全失效**
  → schema:* handler 内 `new SchemaCache(...)`，每次展开树重新 SHOW DATABASES 查库。
  → `registerIpc` 内建 `Map<connectionId, SchemaCache>` 缓存。
- `[2026-08-20 会话7]` **MAX_RESULT_ROWS 主进程 1000 vs 渲染 50000**
  → 主进程早截断不影响功能但"截断提示"与渲染提示的 5 万行不符。
  → `query-service.ts` 统一为 50_000。
- `[2026-08-20 会话7]` **补全 provider 每次 tab 切换重复注册（内存泄漏）**
  → `key={tab.id}` 每次切 tab 卸载/挂载 Editor，beforeMount 内 `registerCompletionItemProvider` 是全局的且从不 dispose。
  → 模块级 `completionProviderRegistered` 守卫只注册一次；修正在模块作用域（不要在组件体内声明守卫变量）。
- `[2026-08-20 会话7]` **快捷键 effect 依赖 ref 不触发首次注册**
  → 依赖 `[monacoRef.current, editorRef.current]`，ref 变化不触发 re-render → 首次打开编辑器 Ctrl+Enter 无响应。
  → 把 `addAction` 移入 `onMount`（此时 editor/monaco 必已就绪），用 `executeRef`/`formatRef` 保持最新回调，`onCleanupRef` 卸载时 dispose。
- `[2026-08-20 会话7]` **ObjectExplorer 切换连接数据竞争**
  → 仅首次 databases 请求有 cancelled 保护，loadTables/loadColumns 无取消 → 旧连接响应覆盖新连接状态。
  → `requestIdRef` 请求令牌，每次响应校验 token。
- `[2026-08-20 会话7]` **Favorites 重名冲突不可删除**
  → 重名文件 `name (2).sql` 但 meta.name 仍是原名 → 列表显示两个同名 → 删除永远指向第一个。
  → `meta.name` 跟随实际文件名；`removeFavorite` 增加目录扫描按 meta.name 匹配。
- `[2026-08-20 会话7]` **schema-cache SQL 无转义 / dataPreview 无转义**
  → 表名/库名直接拼进 `SHOW FULL TABLES FROM ``${db}`` 等，注入风险。
  → `esc(name)` = `name.replace(/`/g, '``')`。
- `[2026-08-20 会话7]` **编辑连接时空密码覆盖已有密码**
  → `ConnectionInput.password` 可选，更新时 `encrypt('')` 覆盖原密码。

## §10 常用排障

| 症状 | 排查/处理 |
|---|---|
| `dev` 起不来，Electron 白屏 | 先确认 `dist/main/main.cjs` 存在（dev 脚本会先 build:main）；看 `dev-smoke.log` 或终端输出 |
| Vite 端口占用 | 改 `vite.config.ts` server.port，并同步改 package.json 的 `dev:electron`/`dev:renderer` 里 5173 |
| 组件测试跑在 node 环境报 DOM API 错误 | 文件头加 `// @vitest-environment jsdom` |
| 原生模块报 ABI mismatch | 跑 `npm run rebuild`（electron-rebuild 重编 better-sqlite3） |
| 主进程 require 不到 npm 包 | 该包被 external 了，运行时从 node_modules 加载 → 确认 `package.json` dependencies 里有它（不是 devDependencies） |
| 渲染构建报 `Rollup failed to resolve import` | 检查 `vite.config.ts` 别名是否与 tsconfig 同步 |
| tsc 报 `cannot find module` monaco-editor 类型 | `import type` 从 `monaco-editor/esm/vs/editor/editor.api` 导入，或使用本地结构类型 |
| IPC handler 未注册 | 检查 `ipc.ts` 的 `registerIpc` 是否注册了该 channel，且 `ipc-contract.ts` 的 `IPC_CHANNELS` 包含该常量 |
| 测试报 `navigator.clipboard is undefined` | jsdom 未实现 clipboard。在 test 的 beforeEach 中 `Object.defineProperty(navigator, 'clipboard', ...)` |
| 测试报 `zustand store state leaked` | 在 beforeEach 中重置 `useWorkspace.setState({ tabs: [], ... })` |
| CI 构建失败 | 登录 GitHub Actions 查看 logs，常见原因见架构文档 §9 CI/CD 构建指南 |
