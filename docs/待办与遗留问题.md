## 4. 本次修复记录（2026-09-16）

### 4.1 代码审查发现并修复（P0 + P1）

| 级别 | 问题 | 修复 |
|---|---|---|
| **P0** | 连接编辑表单无 `key`，切换编辑目标时把 A 的配置静默覆盖到 B | `ConnectionManager.tsx` 加 `key={editing?.id ?? 'new'}` |
| P1 | Excel 导出用列名作列 key，JOIN 同名列后值覆盖前值 | `excel-exporter.ts` 列 key 改用下标 `col_${idx}` |
| P1 | 一条坏密文导致整个连接列表加载失败 | `metadata-store.ts` 摘要路径改走**不解密**的 `rowToSummary`；`rowToConfig` 解密失败隔离为空密码并告警 |
| P1 | `b64:` 降级密文 / 历史明文在 safeStorage 环境下解不开 | `security.ts` 三种格式各自解码；`hex:` 在无 safeStorage 时给明确错误（而非 TypeError）；明文原样返回 |
| P1 | 预载表请求读了序号却不比较 → 切连接后旧表写进新连接 | `ObjectExplorer.tsx` 引入**连接代际 `epochRef`**，所有异步响应回来校验代际 |
| P1 | `loadTables` / `loadColumns` 共用自增计数器互相作废 → 节点永久空白 | 改为只读代际，不同节点之间不再互相取消 |
| P1 | 字段缓存键不含连接维度 → 切连接显示上个连接的字段 | `TableFieldsPanel.tsx` 连接变化时清空缓存 + 作废在途请求；过期响应把 loading 落下（不再永久转圈） |
| P1 | 删除任意连接都清空当前选中 → 中断正在使用的会话 | 仅当 `id === selectedId` 时才清空 |
| P1 | AI 请求超时双源（Main 硬编码 15s vs 设置面板可调 3-60s） | `ai-service.ts` 改用共享归一化的 `rateLimit.requestTimeoutMs` |
| P1 | `AiService` 用 `console.log`，打包后主进程日志全部丢失 | 注入日志出口到持久日志（`event: ai.request`），无 sink 时退化 console |
| — | 日志 `flush()` 中的无意义表达式 | 清理并修正注释：electron-log file transport **默认 `sync: true`**，落盘本无问题（原先「未设 sync 是缺陷」的判断已更正） |

### 4.2 用户反馈的运行时缺陷

| 现象 | 根因 | 修复 |
|---|---|---|
| 白天模式下编辑器启动仍为深色，切换一次主题才正常 | `updateOptions({ theme })` 不是合法 editor option（被 Monaco 静默忽略）；且 `onMount` 闭包里的 `theme` 恒为首次渲染值 | `SqlEditor.tsx` 新增 `themeRef` 实时镜像，`onMount` 与 `[theme]` effect 均调用 `monaco.editor.setTheme()` |
| AI 补全「再也触发不了」 | 把 Monaco 的 `disposeInlineCompletions`（**结果级回收**，reason: lostRace/notTaken/empty…）误当 provider 销毁 → `cancelled = true` 永久失效 | `ai-provider.ts` 改为 no-op，provider 生命周期只由 `dispose()` 控制 |
