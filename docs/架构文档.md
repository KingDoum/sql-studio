# SQL Studio 架构文档

> 本文档描述当前源码真实形成的系统架构，是 SQL Studio 后续开发、重构和验收的技术基线。
> 文档结论以 `src/`、`tests/`、`package.json` 和实际命令输出为准；历史会话中的完成数字不具有约束力。
> 待办与已知问题不在此维护，见 `docs/待办与遗留问题.md`。

## 1. 项目定位

SQL Studio 是面向数据分析师的桌面级 SQL 工具，目标是提供接近 Navicat/DataGrip 的 MySQL/MariaDB 工作台能力：数据库连接管理、Schema 浏览、SQL 编辑、查询执行、结果查看、数据导出、执行历史、命名收藏、AI SQL 补全、自动保存与工作区恢复、持久化调试日志和多主题外观。

当前实现是单机桌面应用，不包含独立后端服务。数据库连接、密码解密、文件读写和外部 AI API 调用均由 Electron 主进程完成。

## 2. 总体架构

```text
+---------------------------+
| Renderer: React + Monaco  |
| UI / Zustand / pure libs  |
+-------------+-------------+
              | window.sqlStudio
+-------------v-------------+
| Preload: contextBridge    |
| typed IPC invoke/unpack   |
+-------------+-------------+
              | ipcRenderer.invoke
+-------------v-------------+
| Main: Electron + Node.js  |
| IPC router + services     |
+------+----------+---------+
       |          |
       |          +--------------------+
       v                               v
 MySQL/MariaDB                 SQLite / local files / AI API / log files
```

### 2.1 进程边界

| 进程 | 主要职责 | 禁止事项 |
|---|---|---|
| Renderer | React UI、Monaco 编辑器、交互状态、纯逻辑 | 不连接 MySQL；不读取 SQLite；不读写任意文件；不持有解密密码 |
| Preload | 通过 `contextBridge` 暴露类型化 API，转发 IPC | 不实现业务逻辑；不暴露 `ipcRenderer` 原对象 |
| Main | 服务初始化、IPC 路由、数据库和文件访问、加密、AI 调用、持久日志 | 不把密码和敏感配置返回 Renderer |

Electron 窗口当前使用 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: false`。其中 `sandbox: false` 是当前实现对原生模块和 preload 的兼容选择，后续如要开启 sandbox，需要单独验证 better-sqlite3、preload 和文件能力。

## 3. 启动与生命周期

入口文件：`src/main/index.ts`。

启动顺序：

1. Electron `app.whenReady()` 完成。
2. 创建 `Security`。
3. 使用 `app.getPath('userData')` 确定 SQLite 数据库路径 `sql-studio.db`。
4. 创建 `MetadataStore`（含 schema v1→v2 迁移）、`ConnectionManager`、`FavoritesStore`、`WorkspaceRecoveryStore`（与 MetadataStore 共用同一 SQLite 连接）、`PersistentLogService`。
5. 调用 `registerIpc()` 注册 IPC handler，注入全部服务单例。
6. 创建 BrowserWindow，加载 preload 和 Renderer。
7. 注册崩溃与异常事件（`uncaughtException`、`unhandledRejection`、`render-process-gone`、`unresponsive`、`did-fail-load`）到持久日志。
8. 应用退出：`will-quit` + `preventDefault`，await `connectionManager.closeAll()`（含失败兜底与 3s 超时）和日志 flush 后再 `app.quit()`，并用防重入标志避免循环。

开发模式通过 `VITE_DEV_SERVER_URL` 加载 Vite 地址，生产模式加载 `dist/renderer/index.html`。主进程和 preload 构建为 `.cjs`，因为 `package.json` 声明了 `type: module`，Electron 主进程仍需要 CommonJS 产物。

## 4. 服务层

### 4.1 Security

文件：`src/main/services/security.ts`

职责：

- Electron 环境优先使用 `safeStorage.encryptString/decryptString`。
- 二进制密文以 `hex:` 前缀写入 SQLite。
- 非 Electron 或 safeStorage 不可用时使用 `b64:` 前缀兼容方案。
- 兼容无前缀历史数据。
- 对外暴露 `encryptionAvailable` 供判断是否走真加密。

`decrypt()` 按密文前缀分三条**互相独立**的解码路径，不一律交给「当前加密器」：

| 前缀 | 含义 | 解密方式 |
|---|---|---|
| `hex:` | safeStorage 二进制密文 | 仅当 safeStorage 可用时解；不可用时抛可读错误（换机器/换用户属预期情形） |
| `b64:` | 无 safeStorage 环境的降级密文 | **固定走 base64 解码**；若交给当前加密器（safeStorage），会因收到字符串而失败 → 历史密码永久解不开 |
| 无分隔符 | 极早期直接落库的明文 | 原样返回（兼容） |

其他前缀（如未来扩展的 `aes:`）抛「不支持的密文格式」，不静默返回错误数据。

重要边界：`b64:` 只是编码，不是加密。生产环境必须检查 `encryptionAvailable`，不能把 base64 当作安全保护。**当前 UI 尚未在降级状态下给出风险提示**（见 `待办与遗留问题.md` #11）。

### 4.2 MetadataStore

文件：`src/main/services/metadata-store.ts`

使用 better-sqlite3，数据库位于 Electron `userData` 目录。当前 schema 为 v2，初始化表：

- `meta`：保存 `schema_version`。
- `connections`：连接基本信息和密码密文。
- `history`：执行历史。
- `settings`：通用设置、AI 设置和 AI 请求策略。
- `workspace_snapshots` / `workspace_tabs`（v2 新增）：自动保存的工作区快照与标签，含索引、外键 `ON DELETE CASCADE` 与容量上限。

v1→v2 迁移为显式版本迁移：单事务、失败回滚、可重复执行（幂等），旧连接与密码密文完整保留。`getSharedDatabase()` 提供受控的连接共享给 `WorkspaceRecoveryStore`。

连接读取分为两种模型：

- `ConnectionSummary`：返回 Renderer，不含 password。
- `ConnectionConfig`：仅主进程内部使用，包含解密后的 password。

连接编辑时，如果已有连接且提交的 password 为空，会保留旧密码密文。连接删除由 IPC 层先关闭连接池，再删除 SQLite 记录。

**摘要路径不解密**：`rowToSummary()` 直接按行映射，供 `listConnections` / `getConnection` / 保存后回显使用 —— 因此单条密文损坏**不会**让整个连接列表加载失败。`rowToConfig()`（内部配置路径）解密失败时隔离为「空密码」并告警，由用户编辑该连接重新输入，不向上抛异常。

### 4.3 ConnectionManager

文件：`src/main/services/connection-manager.ts`

职责：

- 按连接 id 管理 MySQL 连接池。
- 连接池默认上限 10，连接超时 10 秒，空闲超时 5 分钟。
- 测试连接使用临时单连接，执行 `SELECT 1` 后关闭。
- `executeMany()` 使用临时连接并开启 `multipleStatements`，将多语句响应归一化为 `RawResultSet[]`；真实 mysql2 返回 `[rowsList, fieldsList]` 形态，已按此归一化。
- 支持通过 AbortSignal 中止正在执行的连接：abort 时硬销毁 stream 并本地 reject `AbortError`（MariaDB 实测约 400ms 生效），避免优雅关闭导致的错误 resolve。

当前实际查询路径需要特别注意：`query:execute` 通过 `executeMany()` 创建临时连接，并不是通过 `getPool()` 取得池连接。文档和后续重构不得把普通查询描述成"始终走连接池"。统一为连接池执行需要先解决多语句、安全选项和取消机制之间的兼容性，再补测试（见 `待办与遗留问题.md` #20）。

### 4.4 SchemaCache

文件：`src/main/services/schema-cache.ts`

按连接创建缓存实例（IPC 层用 `Map<connectionId, SchemaCache>` 持有），缓存内容包括：

- 数据库列表。
- 数据库对应的表和视图。
- `database.table` 对应的字段。
- `database.table` 对应的 DDL。

Schema 查询通过反引号转义数据库、表名，避免标识符注入。缓存是内存级缓存，进程退出后丢失。连接保存或删除时，IPC 层清理对应缓存。

### 4.5 QueryService

文件：`src/main/services/query-service.ts`

职责：

- 接收单条或多条 SQL。
- 按顶层分号拆分语句，忽略字符串和注释中的分号。
- 将原始结果转换为 `QueryResult` / `QueryResultSet`。
- 将 NULL 转为 null，将二进制转为 Uint8Array，将对象转为 JSON 字符串。
- 默认每个结果集最多保留 50,000 行，超出后设置 `truncated`。
- 写操作判定调用共享模块 `src/shared/sql-classify.ts`（Main 与 Renderer 同一实现，不做"无法识别就放行"）。
- 计算耗时：`QueryResultSet.elapsedMs` 是该结果集完成归一化时相对查询开始的累计耗时（单调递增，趋近 `totalElapsedMs`）。

执行器通过依赖注入提供。查询取消链路已完整贯通：`query:cancel` → `AbortController.abort` → `makeExecutor` 透传 signal → `ConnectionManager.executeMany(signal)` → `conn.destroy()`。

### 4.6 WorkspaceRecoveryStore

文件：`src/main/services/workspace-recovery-store.ts`

职责：

- 与 `MetadataStore` 共用同一 SQLite 连接和事务边界（`getSharedDatabase()` 受控注入）。
- `load` / `save` / `clear` 工作区快照与标签。
- revision 防护：防止旧快照覆盖新快照。
- 逐行校验与坏标签隔离：单行损坏时隔离该行、恢复其余；未知版本整体隔离。
- 容量上限与超限清理。

`activeTabId` 无效时回退到第一个有效标签，无标签时为 null。**不持久化** query execution、结果集和 executing 状态。

### 4.7 PersistentLogService 与 LogRedaction

文件：`src/main/services/persistent-log-service.ts`、`src/main/services/log-redaction.ts`

职责：

- 使用 `electron-log` 5.4.4（`electron-log/main`），自定义 `format` 输出**单行 JSON**，便于逐行解析。
- 落盘为**同步写**（file transport 默认 `sync: true`），崩溃前最后几条日志不会滞留在内存缓冲；`flush()` 仅做文件句柄兜底。
- 自定义 `archiveLogFn` 轮转归档：10 MiB 触发、保留 5 份归档、14 天、总量 60 MiB。
- 受控路径：`userData/logs/`；`clear()` 只清理受控日志文件。
- `read` 最近 500 条，坏行计数不抛错。
- `log-redaction` 双层脱敏（键名/文本/URL/连接串）：不记录密码、API Key 和完整敏感 SQL。
- 主进程崩溃事件（`uncaughtException`、`unhandledRejection`、`render-process-gone`、`unresponsive`、`did-fail-load`、`child-process-gone`）统一落盘。

**不使用 electron-log 的 `eventLogger`**：它会绕过本项目的日志脱敏链路直接写文件；改为手动注册等价事件，统一走 `logService.append`（受控路径 + 脱敏 + 轮转）。

### 4.8 文件与导出服务

- `ScriptStore`：读写用户自选路径下的 SQL 文件；对话框由 IPC 层调用，Store 只负责文件 IO。
- `FavoritesStore`：管理 `userData/queries/*.sql`，文件头保存 name、connection、tags、createdAt 元信息；`readFavorite` / `removeFavorite` / `renameFavorite` 统一走 `resolveFavoritePath`（文件名精确 + meta.name 回扫）。
- `ExcelExporter`：ExcelJS 生成 xlsx，支持表头样式、冻结首行和元信息 sheet。列 key 使用**列下标**而非列名（结果集可能含 JOIN 同名列，用列名会导致后值覆盖前值）。
- `CsvExporter`：UTF-8 BOM、RFC 4180 字段转义、Excel 公式注入前缀防护、WritableStream backpressure。
- `SqlExporter`：生成批量 INSERT SQL，处理 NULL、数字、布尔值、字符串和二进制；`escapeIdent` / `resolveTableIdent` 统一反引号转义并拒绝 SQL 片段，`validateBatchSize` 拒绝 0/负数/非整数。

收藏按文件名处理重名，保存时自动生成 `name (2).sql`；`sanitizeFileName` 处理 Windows 保留设备名、纯点名和超长名。

## 5. Renderer 架构

入口：`src/renderer/main.tsx`（负责 Monaco loader 预热与本地加载配置，生产不依赖 CDN）。

主编排组件：`src/renderer/App.tsx`（当前 700 行量级，仍是主要编排入口，拆分见 `待办与遗留问题.md` #16）。

当前工作台包含：

- `ConnectionManager`：连接列表（两行布局）和连接表单；编辑/测试/删除收进"更多"菜单。
- `ObjectExplorer`：数据库、表、字段懒加载，查看 DDL 和数据预览；顶部筛选框支持表名+库名模糊匹配（关键词 ≥2 字符自动预载所有库的表）；`.db-list` 是唯一纵向滚动容器。
- `EditorTabs`：多标签、脏状态、打开、保存、另存为、关闭确认。
- `SqlEditor`：Monaco、SQL 补全（支持跨库）、语义高亮、格式化、执行、Ctrl+S 保存、AI 行内补全。
- `TableFieldsPanel`：编辑器右侧表字段导航竖条，自动识别当前 SQL 用到的表（含子查询、跨库），点表展开字段+注释、多表切换、点字段插入纯字段名、宽度可拖拽。
- `ResultTabs` / `ResultGrid`：多结果集、虚拟列表、排序、筛选、复制；顶部「结果历史」横条保留最近 10 次执行结果；表头/筛选/表体共享同一横向滚动容器。
- `DataPreviewModal`：960px 宽 + 横向滚动的数据预览。
- `ExportMenu`：Excel、CSV、SQL INSERT 导出。
- `HistoryPanel` / `FavoritesPanel`：执行历史与文件式收藏，均接入统一 `Modal`。
- `Modal`：统一弹窗组件（遮罩/Escape/关闭/底部操作区/`aria-labelledby`/打开聚焦）。
- `AiSettingsPanel`：AI 协议（DeepSeek FIM / OpenAI Chat）、BaseURL、模型、API Key（只拿到 `AiPublicConfig`，无 apiKey）与请求策略（防抖/最小间隔/冷却/超时）。
- `AppearancePanel`：三套主题（dark / light / titanium）、字号（10-30）与字体。
- `SettingsPanel`：调试日志查看（北京时间展示）、复制与清空，经 `logs:read` / `logs:clear`。

辅助库：

- `src/renderer/store/workspace.ts`（Zustand）：当前连接、标签页、活动标签、执行结果、`executionHistory`（最多 10 条）、正在执行的查询、`hydrateFromSnapshot`（恢复时不还原 execution/results/executing）。
- `src/renderer/lib/workspace-persistence.ts`：500ms 防抖自动保存、结构事件立即排队、串行队列 latest-wins、最多 3 次退避重试、hydrate 屏障、退出 flush。**只调 `workspace:save`，绝不调用 `script:save`**。
- `src/renderer/lib/persistent-log-bridge.ts`：warn/error 即时上报、debug/info 批量（20 条或 250ms）、重入防护。
- `src/renderer/lib/debug-log.ts`：双通道门面（内存面板 + Main 持久日志）。
- `src/renderer/lib/ai-provider.ts`：Monaco inline completion provider，原因码日志（disabled/not_configured/debounce/min_interval/cooldown/empty_prefix/timeout/stale_response/provider_empty/error）。
- `src/renderer/lib/file-name.ts`：`timestampSuffix` / `withTimestamp`，导出与另存为共用的默认文件名（带 `YYYYMMDD_HHmmss`）。

### 5.1 渲染层的关键状态机制

- **ObjectExplorer 请求代际**：`epochRef` 在每次重新加载库列表（切换连接 / 手动重试）时递增，所有异步响应回来先校验代际 —— 旧连接的库/表/字段结果一律丢弃，避免跨连接脏写；`loadTables` 与 `loadColumns` **不共享**自增计数器，因此不会互相作废（否则会出现「展开表后再展开库，字段请求被丢弃、节点永久空白」）。
- **TableFieldsPanel 字段缓存**：缓存键为 `db.table`（不含连接维度），因此连接切换时必须清空缓存并作废在途请求；被作废的响应会把该项 `loading` 落回 false，避免标签永久转圈。
- **SqlEditor 主题**：`theme` 通过 `themeRef` 实时镜像，`onMount` 与 `[theme]` effect 都显式调用 `monaco.editor.setTheme()`。不能依赖第三方封装的主题更新时序，也不能用 `updateOptions({ theme })`（`theme` 不是合法的 editor option）。
- **AI provider 生命周期**：Monaco 的 `disposeInlineCompletions()` 是**结果级回收**回调（`reason: lostRace / tokenCancellation / empty / notTaken`），与 provider 销毁无关，必须保持 no-op；把 `cancelled` 置位会导致「补全触发一次后再也不触发」。provider 只在 `dispose()` 时失效。
- **默认文件名**：导出/另存为的默认名带日期时间，用户不起名时可直接回车保存。
- **安全存储提示**：`app:securityStatus` 返回 `encryptionAvailable`；为 false 时状态栏显示「密码为降级存储」（`b64:` 只是编码，不是真加密）。
- **外部文件冲突检测**：打开/保存后记录 `EditorTab.mtimeMs`；保存前用 `script:stat` 对比磁盘 mtime，不一致则弹确认，避免静默覆盖外部编辑（快照恢复的标签无 mtime，首次保存跳过一次检查）。

## 6. IPC 契约

唯一来源：`src/shared/ipc-contract.ts`。新增 channel 必须同时更新请求映射、响应映射、preload 类型和测试。

当前共 **43 个 channel**。handler 按域拆分：`ipc.ts` 只做组装，具体实现在 `ipc-handlers-db.ts` / `ipc-handlers-io.ts` / `ipc-handlers-app.ts`，共享工具与依赖定义在 `ipc-deps.ts`。

| `settings:get` | `{ key }` | `string \| null` |
| `settings:set` | `{ key, value }` | `{ saved }` |
| `dialog:showSaveDialog` | `ShowSaveDialogOptions` | `string \| null` |
| `dialog:showOpenDialog` | `ShowOpenDialogOptions` | `string \| null` |
| `shell:showItemInFolder` | `{ path }` | `{ shown }` |

## 7. 数据流

### 7.1 查询

```text
SqlEditor/App
  -> query:execute(connectionId, sql, clientQueryId)
  -> MetadataStore 解密 ConnectionConfig
  -> ConnectionManager.executeMany
  -> MySQL/MariaDB
  -> QueryService 归一化结果（含 sql-classify 写操作判定）
  -> MetadataStore 自动写入 history
  -> ResultTabs / ResultGrid
```

写操作在 Renderer 初步识别后弹出确认（`sql-classify` 共享判定），但主进程仍把 SQL 当作不可信输入处理。

### 7.2 Schema

```text
ObjectExplorer
  -> schema:* IPC
  -> per-connection SchemaCache
  -> ConnectionManager.executeMany
  -> SHOW DATABASES / SHOW FULL TABLES / SHOW FULL COLUMNS / SHOW CREATE TABLE
```

### 7.3 AI 补全

```text
Monaco inline provider
  -> ai:complete
  -> MetadataStore.getAiConfig()      (内部配置，含解密 apiKey，仅 Main)
  -> Security.decrypt(apiKey)
  -> AiService（按 protocol 选择接口）
  -> deepseek-fim: <base>/beta/completions（读 choices[0].text，不发送 messages）
     openai-chat : <base>/v1/chat/completions（读 choices[0].message.content）
```

BaseUrl 规范化由 `src/shared/ai-protocol.ts` 统一处理（不重复拼接 `/beta`、`/v1`、`/completions`）；`max_tokens` 钳制在 1..4096。请求策略（防抖/最小间隔/冷却/超时）来自 `AiRateLimitConfig`，Provider 不再写死常量，缺失/越界/NaN 由共享归一化修正。

API Key 分层：`AiConfig`（含明文 Key）只在 Main 内部；Renderer 通过 `settings:getAiConfig` 只拿到 `AiPublicConfig`。设置面板保存时空 Key 由主进程保留旧密文。

请求超时与 Renderer **同源**：`AiService` 使用 `normalizeAiRateLimitConfig(config.rateLimit).requestTimeoutMs`（设置面板可调、共享归一化），不再硬编码，避免「设置 60s 但 Main 15s 先断」。

日志不得输出 API Key。`AiService` 与 `ai-provider` 只输出 URL 摘要、protocol、prefixLen、suffixLen、suggestionLen、HTTP 状态与丢弃原因。`AiService` 的日志经**构造时注入的日志出口**写入持久日志（`event: ai.request`）—— 打包后主进程 `console` 不可见；未注入 sink 时（单测/纯 Node）退化为 console，格式保持 `key=value`。

### 7.4 自动保存与恢复

```text
workspace store 变更
  -> workspace-persistence（500ms 防抖 / 结构事件立即 / latest-wins / 退避重试）
  -> workspace:save（revision 递增）
  -> WorkspaceRecoveryStore -> SQLite（与 MetadataStore 同一连接）

启动
  -> workspace:load -> hydrateFromSnapshot（不还原 execution/results/executing）
  -> 连接失效回退 null；失败则空工作区启动，不白屏
```

### 7.5 持久日志

```text
Renderer debug-log / persistent-log-bridge
  -> logs:append（warn/error 即时、debug/info 批量）
  -> log-redaction 双层脱敏
  -> PersistentLogService（electron-log JSON 行 + 轮转归档）-> userData/logs/
Main 崩溃事件 ────────────────────────────────┘
```

## 9. 安全设计

- Renderer 使用 contextIsolation 和 nodeIntegration=false。
- 连接摘要禁止包含 password；`AiPublicConfig` 禁止包含 apiKey。
- SQLite 只保存密码密文，不保存明文密码。
- SQL 标识符通过反引号转义；导出侧拒绝把 SQL 片段当标识符。
- CSV 对公式前缀进行防注入处理。
- 日志双层脱敏，禁止 API Key、密码和完整敏感 SQL。
- 工作区快照字段白名单，不含任何凭据；自动保存不写真实 `.sql` 文件。
- 所有文件路径来自主进程文件对话框或用户明确选择；路径与设置 key 的运行时校验仍待补（见 `待办与遗留问题.md` #12）。
- SQL 写入确认不能代替数据库权限控制，生产数据库账号仍应遵循最小权限。

## 11. 架构变更规则

1. 先更新 `src/shared/types.ts` / `src/shared/ipc-contract.ts`，再实现 handler、preload、Renderer 和测试。
2. 服务层必须保持依赖注入，纯逻辑优先放在无 Electron 依赖的模块。
