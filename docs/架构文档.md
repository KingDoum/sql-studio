# SQL Studio 架构文档

> 本文档描述当前源码真实形成的系统架构，是 SQL Studio 后续开发、重构和验收的技术基线。
> 文档结论以 `src/`、`tests/`、`package.json` 和实际命令输出为准；历史会话中的完成数字不具有约束力。

## 1. 项目定位

SQL Studio 是面向数据分析师的桌面级 SQL 工具，目标是提供接近 Navicat/DataGrip 的 MySQL/MariaDB 工作台能力：数据库连接管理、Schema 浏览、SQL 编辑、查询执行、结果查看、数据导出、执行历史、命名收藏和 AI SQL 补全。

当前实现是单机桌面应用，不包含独立后端服务。数据库连接、密码解密、文件读写和外部 AI API 调用均由 Electron 主进程完成。

## 2. 总体架构

```text
+---------------------------+
| Renderer: React + Monaco  |
| UI / Zustand / pure libs  |
+-------------+-------------+
              | window.sqlStudio
+-------------v-------------+
| Preload: contextBridge    |
| typed IPC invoke/unpack   |
+-------------+-------------+
              | ipcRenderer.invoke
+-------------v-------------+
| Main: Electron + Node.js  |
| IPC router + services     |
+------+----------+---------+
       |          |
       |          +--------------------+
       v                               v
 MySQL/MariaDB                 SQLite / local files / AI API
```

### 2.1 进程边界

| 进程 | 主要职责 | 禁止事项 |
|---|---|---|
| Renderer | React UI、Monaco 编辑器、交互状态、纯逻辑 | 不连接 MySQL；不读取 SQLite；不读写任意文件；不持有解密密码 |
| Preload | 通过 `contextBridge` 暴露类型化 API，转发 IPC | 不实现业务逻辑；不暴露 `ipcRenderer` 原对象 |
| Main | 服务初始化、IPC 路由、数据库和文件访问、加密、AI 调用 | 不把密码和敏感配置返回 Renderer |

Electron 窗口当前使用 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: false`。其中 `sandbox: false` 是当前实现对原生模块和 preload 的兼容选择，后续如要开启 sandbox，需要单独验证 better-sqlite3、preload 和文件能力。

## 3. 启动与生命周期

入口文件：`src/main/index.ts`。

启动顺序：

1. Electron `app.whenReady()` 完成。
2. 创建 `Security`。
3. 使用 `app.getPath('userData')` 确定 SQLite 数据库路径 `sql-studio.db`。
4. 创建 `MetadataStore`、`ConnectionManager` 和 `FavoritesStore`。
5. 调用 `registerIpc()` 注册 IPC handler。
6. 创建 BrowserWindow，加载 preload 和 Renderer。
7. 应用退出时调用 `connectionManager.closeAll()`。

开发模式通过 `VITE_DEV_SERVER_URL` 加载 Vite 地址，生产模式加载 `dist/renderer/index.html`。主进程和 preload 构建为 `.cjs`，因为 `package.json` 声明了 `type: module`，Electron 主进程仍需要 CommonJS 产物。

## 4. 服务层

### 4.1 Security

文件：`src/main/services/security.ts`

职责：

- Electron 环境优先使用 `safeStorage.encryptString/decryptString`。
- 二进制密文以 `hex:` 前缀写入 SQLite。
- 非 Electron 或 safeStorage 不可用时使用 `b64:` 前缀兼容方案。
- 兼容无前缀历史数据。

重要边界：`b64:` 只是编码，不是加密。生产环境必须检查 `encryptionAvailable`，不能把 base64 当作安全保护。后续可考虑 safeStorage 不可用时拒绝保存密码，或增加明确的“不安全存储”状态提示。

### 4.2 MetadataStore

文件：`src/main/services/metadata-store.ts`

使用 better-sqlite3，数据库位于 Electron `userData` 目录。当前初始化表：

- `meta`：保存 `schema_version`。
- `connections`：连接基本信息和密码密文。
- `history`：执行历史。
- `settings`：通用设置和 AI 设置。

连接读取分为两种模型：

- `ConnectionSummary`：返回 Renderer，不含 password。
- `ConnectionConfig`：仅主进程内部使用，包含解密后的 password。

连接编辑时，如果已有连接且提交的 password 为空，会保留旧密码密文。连接删除由 IPC 层先关闭连接池，再删除 SQLite 记录。

### 4.3 ConnectionManager

文件：`src/main/services/connection-manager.ts`

职责：

- 按连接 id 管理 MySQL 连接池。
- 连接池默认上限 10，连接超时 10 秒，空闲超时 5 分钟。
- 测试连接使用临时单连接，执行 `SELECT 1` 后关闭。
- `executeMany()` 使用临时连接并开启 `multipleStatements`，将多语句响应归一化为 `RawResultSet[]`。
- 支持通过 AbortSignal 销毁正在执行的连接。

当前实际查询路径需要特别注意：`query:execute` 通过 `executeMany()` 创建临时连接，并不是通过 `getPool()` 取得池连接。文档和后续重构不得把普通查询描述成“始终走连接池”。如果要统一为连接池执行，需要先解决多语句、安全选项和取消机制之间的兼容性，再补测试。

### 4.4 SchemaCache

文件：`src/main/services/schema-cache.ts`

按连接创建缓存实例，缓存内容包括：

- 数据库列表。
- 数据库对应的表和视图。
- `database.table` 对应的字段。
- `database.table` 对应的 DDL。

Schema 查询通过反引号转义数据库、表名，避免标识符注入。缓存是内存级缓存，进程退出后丢失。连接保存或删除时，IPC 层清理对应缓存。

### 4.5 QueryService

文件：`src/main/services/query-service.ts`

职责：

- 接收单条或多条 SQL。
- 按顶层分号拆分语句，忽略字符串和注释中的分号。
- 将原始结果转换为 `QueryResult` / `QueryResultSet`。
- 将 NULL 转为 null，将二进制转为 Uint8Array，将对象转为 JSON 字符串。
- 默认每个结果集最多保留 50,000 行，超出后设置 `truncated`。
- 推断是否包含写操作，并计算总耗时。

`QueryService` 的执行器通过依赖注入提供。当前 `QueryResultSet.elapsedMs` 实际返回 0，只有聚合层 `totalElapsedMs` 有真实耗时；如果 UI 需要逐结果集耗时，应在服务层补齐并增加测试。

查询取消现状：Renderer 传入 `clientQueryId`，IPC 层创建 AbortController，`makeExecutor()` 已把 signal 透传给 `executeMany()`，`executeMany()` 在 abort 时销毁临时连接以中止 MySQL 查询。取消链路已完整贯通（`query:cancel` → AbortController.abort → signal → conn.destroy）。

### 4.6 文件与导出服务

- `ScriptStore`：读写用户自选路径下的 SQL 文件。
- `FavoritesStore`：管理 `userData/queries/*.sql`，文件头保存 name、connection、tags、createdAt 元信息。
- `ExcelExporter`：ExcelJS 生成 xlsx，支持表头样式、冻结首行和元信息 sheet。
- `CsvExporter`：UTF-8 BOM、RFC 4180 字段转义、Excel 公式注入前缀防护、WritableStream backpressure。
- `SqlExporter`：生成批量 INSERT SQL，处理 NULL、数字、布尔值、字符串和二进制。

收藏按文件名处理重名，保存时自动生成 `name (2).sql`。删除和重命名支持按元信息回扫，但 `readFavorite()` 当前主要按文件名精确定位，三者定位规则尚未完全统一。

## 5. Renderer 架构

入口：`src/renderer/main.tsx`。

主编排组件：`src/renderer/App.tsx`。

当前工作台包含：

- `ConnectionManager`：连接列表和连接表单。
- `ObjectExplorer`：数据库、表、字段懒加载，查看 DDL 和数据预览；顶部筛选框支持表名+库名模糊匹配（2026-08-31 新增，关键词 ≥2 字符自动预载所有库的表）。阶段 6 起 `.db-list` 是唯一纵向滚动容器（库/表/字段统一由它滚动），`.explorer` 具备稳定高度约束。
- `EditorTabs`：多标签、脏状态、打开、保存、另存为。
- `SqlEditor`：Monaco、SQL 补全、语义高亮、格式化、执行、AI 行内补全。
- `TableFieldsPanel`（2026-08-31 新增）：编辑器右侧表字段导航竖条，自动识别当前 SQL 用到的表（含子查询、跨库），点表展开字段+注释、多表切换、点字段插入纯字段名，宽度可拖拽。
- `ResultTabs` / `ResultGrid`：多结果集、虚拟列表、排序、筛选、复制；结果区顶部有「结果历史」横条（保留最近 10 次执行结果，可点击切换）；表格用统一横向滚动容器（表头/筛选/表体共享同一 x-scroll host，列多可横滚看全；阶段 5 起补足 flex 约束 + 清晰滚动条 + 0 行多列仍保留表头）。
- `ExportMenu`：Excel、CSV、SQL INSERT 导出。
- `HistoryPanel`：执行历史搜索、回填和删除。
- `FavoritesPanel`：文件式收藏查看、打开、重命名和删除。
- `AiSettingsPanel`：AI 补全设置（协议选择 DeepSeek FIM / OpenAI Chat，BaseURL、模型、API Key）。阶段 3 起设置面板只拿到 `AiPublicConfig`（无 apiKey，仅 `apiKeyConfigured` 布尔），旧 Key 不会出现在 Renderer。
- `SettingsPanel`：主题、字体（字号 10-30）和调试设置。阶段 4 起调试日志统一按北京时间（Asia/Shanghai）展示与复制，内部仍保存 ISO UTC。

Zustand store 位于 `src/renderer/store/workspace.ts`，保存当前连接、标签页、活动标签、执行结果、执行结果历史（`executionHistory`，最多 10 条）和正在执行的查询。

`App.tsx` 当前承担较多编排和业务动作，是后续代码优化的主要切入点。拆分时应按“脚本工作流、查询工作流、收藏工作流、外观设置”分离，并保持 IPC 调用仍从 Renderer 经 preload 完成。

## 7. 数据流

### 7.1 查询

```text
SqlEditor/App
  -> query:execute(connectionId, sql, clientQueryId)
  -> MetadataStore 解密 ConnectionConfig
  -> ConnectionManager.executeMany
  -> MySQL/MariaDB
  -> QueryService 归一化结果
  -> MetadataStore 自动写入 history
  -> ResultTabs / ResultGrid
```

写操作在 Renderer 初步识别后弹出确认，但主进程仍应把 SQL 当作不可信输入处理。后续应把写操作确认和 SQL 分类逻辑集中到共享或主进程可测试模块，避免只依赖 UI。

### 7.2 Schema

```text
ObjectExplorer
  -> schema:* IPC
  -> per-connection SchemaCache
  -> ConnectionManager.executeMany
  -> SHOW DATABASES / SHOW FULL TABLES / SHOW FULL COLUMNS / SHOW CREATE TABLE
```

### 7.3 AI 补全

```text
Monaco inline provider
  -> ai:complete
  -> MetadataStore.getAiConfig()      (内部配置，含解密 apiKey，仅 Main)
  -> Security.decrypt(apiKey)
  -> AiService
  -> protocol === 'deepseek-fim' ? <base>/beta/completions : <base>/v1/chat/completions
```

阶段 1（2026-09-01）起，AiService 按 `protocol` 显式选择接口：

- `deepseek-fim`：DeepSeek 官方 FIM 接口（`https://<base>/beta/completions`），请求体 `{model, prompt, suffix, max_tokens, temperature, stream:false}`，**不发送 messages**，响应读 `choices[0].text`。
- `openai-chat`：OpenAI 兼容接口（`/v1/chat/completions`），响应读 `choices[0].message.content`，保留兼容。

BaseUrl 规范化由 `src/shared/ai-protocol.ts` 统一处理（不重复拼接 `/beta`、`/v1`、`/completions`）；旧配置无 `protocol` 时按 baseUrl 含 `/beta` 推断为 FIM，否则 Chat。`max_tokens` 钳制在 1..4096，默认 512。

阶段 3（2026-09-01）起 API Key 分层：`AiConfig`（含明文 Key）只在 Main 内部；Renderer 通过 `settings:getAiConfig` 只拿到 `AiPublicConfig`（无 apiKey，仅 `apiKeyConfigured` 布尔）。设置面板保存时空 Key 由主进程保留旧密文，用户不能通过空输入清空 Key。

日志不得输出 API Key。`AiService` 与 `ai-provider` 日志只输出 URL 摘要、protocol、prefixLen、suffixLen、suggestionLen、HTTP 状态与丢弃原因；不输出完整 prefix/suffix/SQL、Authorization header。

## 9. 安全设计

- Renderer 使用 contextIsolation 和 nodeIntegration=false。
- 连接摘要禁止包含 password。
- SQLite 只保存密码密文，不保存明文密码。
- SQL 标识符通过反引号转义。
- CSV 对公式前缀进行防注入处理。
- 日志只允许输出必要的诊断信息，禁止 API Key、密码和完整敏感 SQL。
- 所有文件路径来自主进程文件对话框或用户明确选择；后续应增加路径规范化和越权路径测试。
- SQL 写入确认不能代替数据库权限控制，生产数据库账号仍应遵循最小权限。

## 11. 架构变更规则

1. 先更新 `src/shared/types.ts` / `src/shared/ipc-contract.ts`，再实现 handler、preload、Renderer 和测试。
2. 服务层必须保持依赖注入，纯逻辑优先放在无 Electron 依赖的模块。
