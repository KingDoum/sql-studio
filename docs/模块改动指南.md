# 模块改动指南

> **用途**：要改某个模块时，先在这里查到「动哪些文件、不能碰什么、跑哪些测试」，不必通读 1.2 万行源码。
> **配套**：`架构文档.md`（系统全貌与不变量）、`开发文档.md`（流程 / 打包 / 排错）、`架构评审报告.md`（结构问题与整改顺序）、`待办与遗留问题.md`（未完成项）

## 0. 三种查法

| 你的处境 | 去哪 |

| 改的是敏感区域（转义、取消、加密、自动保存…） | **§3 高危改动清单**（10 项，动之前必须先看） |

## 2. 模块卡片

### 2.1 共享层 `src/shared/` —— 零依赖，Main/Renderer 都可引用

| 模块 | 职责 | 改动不变量 |
|---|---|---|
| `types.ts` (654) | 全部跨进程数据类型 | ① `ConnectionSummary` **不得含 password**；② `AiPublicConfig` **不得含 apiKey**；③ 改字段必须同步 `ipc-contract.ts` 的 map |
| `ipc-contract.ts` (244) | 43 个 channel + 请求/响应映射 | **唯一来源**：新增 channel 必须同时登记 request/response map；preload 按它自动暴露，不要手写方法 |
| `sql-classify.ts` (294) | 语句风险分类（read / write / unknown） | Main 与 Renderer **必须同一实现**，禁止任何一侧另写判断；无法确定按高风险处理 |
| `ai-protocol.ts` (145) | AI URL 规范化 + 限流参数归一化 | 不重复拼 `/beta`、`/v1`、`/completions`；`max_tokens` 钳 1..4096；缺省/越界/NaN 在这里修正 |
| `sql-ident.ts` | 标识符转义：`escapeIdentRaw`（只转义）/ `quoteIdent`（转义+包裹）/ `quoteQualifiedIdent`（解析 `db.table` 并拒绝 SQL 片段） | **唯一来源** —— 禁止在业务文件里再写 ``replace(/`/g, '``')``；`quoteQualifiedIdent` 负责拒绝 `;` `()` 换行 |
| `column-type.ts` | 列类型判定与归一化：`isNumericColumnType` / `columnTypeFromRaw` / `columnTypeFromCode` | Main（Excel 数值化、结果集表头）与 Renderer（网格右对齐）、SchemaCache（字段列表）共用；**刻意不含 varchar/char**（前导零不该被改写）；`longblob` 统一归 `blob` |

测试：`tests/shared/`（5 个：`ipc-contract` / `sql-classify` / `ai-rate-limit` / `column-type` / `sql-ident`）

### 2.3 主进程服务（14 个，全部有单测）

**Security** · `services/security.ts` (115)
- 职责：safeStorage 优先加密；`hex:` / `b64:` / 无前缀 **三条独立**解密路径
- 🔴 **`b64:` 永远走 base64 解码**，不能交给当前加密器 —— 否则在后来启用 safeStorage 的机器上，历史密码永久解不开
- 测试：`security.test.ts`

**MetadataStore** · `services/metadata-store.ts` (456)
- 职责：SQLite（连接 / 历史 / 设置 / 工作区快照）+ 显式 schema 迁移（当前 v2）
- 🔴 迁移必须**单事务 + 失败回滚 + 幂等**
- 🔴 摘要路径 `rowToSummary` **不解密**（单条坏密文不能拖垮整个列表）；`rowToConfig` 解密失败隔离为「空密码」
- 测试：`metadata-store.test.ts`

**ConnectionManager** · `services/connection-manager.ts` (379)
- 职责：per-id 连接池、`testConnection`、`executeMany`（临时连接 + `multipleStatements`）、错误规范化
- ⚠️ **事实**：普通查询走 `executeMany` 的**临时连接，不是连接池**（有意保留，见待办 #20）。不要顺手"统一成池"
- 取消：abort 时**硬销毁 stream**（`stream.destroy()`）；优雅关闭会让挂起查询错误 resolve
- 测试：`connection-manager.test.ts`

**QueryService** · `services/query-service.ts` (313)
- 职责：语句拆分、列元信息、行归一化（NULL / Buffer / Date / BIT）、5 万行截断、耗时聚合
- 🔴 日期**按列类型**决定是否省略时间（不能靠"时分秒是否为 0"猜，否则 `00:00:00` 的真实时间会被吞掉）
- 🔴 BIT 列**按列类型**转数值（≤48bit → number，超出保持二进制）
- ✅ 列类型归一化已收敛到 `@shared/column-type`（`columnTypeFromCode` / `columnTypeFromRaw`）；**`longblob` 统一归 `blob`**（历史上一处 `text` 一处 `blob`）
- 测试：`query-service.test.ts`

**SchemaCache** · `services/schema-cache.ts` (160)
- 职责：按连接缓存 库 / 表 / 字段 / DDL；`SCHEMA_SQL` 集中常量
- 不变量：库名表名必须经 `quoteIdent`（`@shared/sql-ident`）转义；连接保存/删除后由 IPC 层清缓存
- 测试：`schema-cache.test.ts`

**WorkspaceRecoveryStore** · `services/workspace-recovery-store.ts` (282)
- 职责：工作区快照 load / save / clear、revision 防护、坏行隔离、容量上限
- 🔴 **与 MetadataStore 共用同一 SQLite 连接**（`getSharedDatabase()`），不要另开连接
- 不持久化 execution / results / executing
- 测试：`workspace-recovery-store.test.ts`

**PersistentLogService / LogRedaction** · `services/persistent-log-service.ts` (450) / `log-redaction.ts` (136)
- 职责：electron-log 单行 JSON、同步写、轮转归档、受控路径、双层脱敏
- 🔴 **不使用 electron-log 的 `eventLogger`**（它会绕过脱敏链路直接写文件）
- 🔴 禁止记录密码、API Key、完整敏感 SQL
- 测试：`persistent-log-service.test.ts`、`log-redaction.test.ts`

**AiService** · `services/ai-service.ts` (209)
- 职责：按 protocol 调 DeepSeek FIM / OpenAI Chat
- 🔴 超时必须用 `normalizeAiRateLimitConfig(config.rateLimit).requestTimeoutMs`（与 Renderer **同源**，不要新增硬编码常量）
- 🔴 日志经**构造注入的 sink** 落持久日志；只 `console.log` 在打包后不可见、等于丢日志
- 测试：`ai-service.test.ts`

**导出三件套** · `excel-exporter.ts` (151) / `csv-exporter.ts` (84) / `sql-exporter.ts` (118)
- Excel：列 key **必须用列下标**（`col_${idx}`），用列名会让 JOIN 同名列后值覆盖前值；数值型列的字符串值在**精度安全**时才转数值（整数须 `Number.isSafeInteger`，小数有效数字 ≤15）
- CSV：UTF-8 BOM、RFC 4180、`= + - @` 前缀防公式注入、backpressure
- SQL：`escapeIdent` / `resolveTableIdent` 转义并拒绝片段；`validateBatchSize` 拒 0 / 负数 / 非整数
- 测试：三个 exporter 各自的测试

**ScriptStore / FavoritesStore** · `script-store.ts` (85) / `favorites-store.ts` (267)
- ScriptStore 只做文件 IO（对话框在 IPC 层）；FavoritesStore 管理 `userData/queries/*.sql` + 文件头元信息
- 🔴 读取 / 删除 / 重命名必须统一走 `resolveFavoritePath`
- 🔴 文件名必须 `sanitizeFileName`（Windows 保留设备名、纯点名、超长名）

### 2.4 Preload · `preload/index.ts` (49)

- 只做两件事：按 `IPC_CHANNELS` 构造 API、`invoke` 后解包 `{ok,data}`（失败转 rejected Error）
- 🔴 不得添加业务判断、数据库逻辑或文件操作

## 3. 高危改动清单（动之前必看）

| # | 区域 | 为什么危险 | 改动要点 |
|---|---|---|---|
| 1 | **标识符转义** | ✅ **已收敛到 `@shared/sql-ident`（2026-09-17）**。历史上曾有 3 处实现且两个同名函数语义不同（一个带反引号包裹、一个不带），跨层复制会得到错层引号 | 新代码一律用 `quoteIdent` / `quoteQualifiedIdent` / `escapeIdentRaw`；**不要**再写 ``replace(/`/g, '``')``（已补 `tests/shared/sql-ident.test.ts` 守住语义） |
| 2 | **查询取消链路** | 5 层贯通，任一层丢 signal 都会变成"只改 UI 不断查询" | App `clientQueryId` → `queryAborters` → `QueryService signal` → `makeExecutor` → `executeMany(signal)` → `stream.destroy()` |
| 3 | **密码解密前缀分流** | `b64:` 只是编码，交给 safeStorage 会永久解不开 | `hex:` / `b64:` / 无前缀 三条路径保持独立 |
| 4 | **Excel 列 key** | 用列名会让 JOIN 同名列互相覆盖 | 用 `col_${idx}` 下标 |
| 5 | **自动保存** | 写错文件会污染用户的真实脚本 | 只调 `workspace:save`；快照白名单不含凭据 |
| 6 | **Monaco 两条语义** | 都是"看起来能跑但行为错"的陷阱 | `setTheme()` 而非 `updateOptions({theme})`；`disposeInlineCompletions` 保持 no-op |
| 7 | **SQLite schema 迁移** | 失败会损坏用户数据 | 单事务 + 失败回滚 + 幂等；与 WorkspaceRecoveryStore 共用同一连接 |
| 8 | **IPC 契约变更** | 顺序错会留下不一致的中间状态 | `types` → `ipc-contract` → handler →（preload 自动）→ renderer → 测试 |
| 9 | **better-sqlite3 ABI** | 打包后会变成 Electron ABI，测试直接报错 | 见 `开发文档.md` §10.3-3 的恢复命令 |
| 10 | **BIT / 日期归一化** | 靠值猜会丢信息（`00:00:00` 是真实时间） | 一律**按列类型**判断，不要按取值形态猜 |

## 4. 验证命令速查

```bash
# 最小验证（任何改动都要过）
npm run typecheck && npm test

# 分层跑
npx vitest run tests/main/          # 主进程与服务
npx vitest run tests/renderer/      # 组件与纯逻辑
npx vitest run tests/shared/        # 契约与共享逻辑

# 单文件 / 按用例名过滤
npx vitest run tests/main/query-service.test.ts
npx vitest run -t 'BIT'

# 完整构建
npm run build

# 打包（免安装版，本地调试首选）
npm run package:dir

# UI 设计前后对比（需先 build；playwright 被 npm 清掉时先重装）
npm i --no-save playwright && node tests/e2e/ui-audit.mjs
```

**完成标准**（`开发文档.md` §13）：`typecheck` + `test` + `build` 三条命令全部通过；涉及 Electron / MySQL / 文件对话框 / 查询取消时，另按 `e2e-checklist.md` 做端到端冒烟。

## 5. 维护规则

1. **新增模块 → 必须在这里加一张卡片**，否则下次改动又会退化成"通读 1.2 万行源码"。
2. 卡片只写**改动时要遵守 / 要同步的信息**，不要复述架构文档已有的设计描述（避免两处维护）。
3. **会漂移的数字**（channel 数、文件行数、用例数）只在 `架构文档.md` / `开发文档.md` 各维护一处，本指南不复述。
4. 把某处重复实现收敛成单一来源后，**在 §3 高危清单留一条说明**，防止后人再次复制出去。
