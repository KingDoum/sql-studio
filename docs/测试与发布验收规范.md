# SQL Studio 测试与发布验收规范

> 用途：统一 SQL Studio 的测试分层、真实环境验证、发布阻断条件和回退要求。
> 项目路径：`/vol1/1000/docker/Services/deepseek-harness/DSH_projects/sql_plus/SQL_project`
> 编写日期：2026-08-30

## 1. 验证分层

### L1：静态与类型

- `npm run typecheck`
- 检查共享类型、IPC channel、路径和依赖边界。
- 失败时不得进入下一阶段。

### L2：单元与组件

- `npm test`
- Main、Renderer、Shared 测试必须同时执行。
- 记录实际测试文件数、用例数、失败用例和环境信息。

### L3：构建

- `npm run build`
- 确认 Main、Preload、Renderer 产物生成。
- 确认 preload 使用 `preload.cjs`，生产 Renderer 不依赖 CDN。

### L4：无头 E2E

- `node tests/e2e/ui-layout-check.mjs`
- `node tests/e2e/ui-state-check.mjs`
- 覆盖窗口尺寸、执行中、错误、截断、Modal、菜单、结果区拖拽和无横向溢出。

### L5：真实 Electron 与数据库

必须在 Windows 图形环境和可用 MySQL/MariaDB 测试库执行：

- 启动 Electron。
- 新增、测试、保存、切换和删除连接。
- Schema 懒加载、表/字段双击行为。
- 单语句、多语句、读写混合、CTE、CALL、取消和截断。
- 历史、收藏、打开、保存、另存为。
- Excel、CSV、SQL INSERT 导出。
- 错误、取消、覆盖确认和权限失败。

## 2. 每次代码变更的证据

每个阶段报告必须包含：

- 修改文件和未修改的边界文件。
- 行为变化和兼容性说明。
- 运行的命令及退出码。
- 实际测试文件/用例统计。
- 真实环境、Node、npm、Electron、数据库版本。
- 截图、日志或数据库结果等必要证据。
- 已知限制、回退方式和下一步决策门。

## 3. 发布阻断条件

出现以下任一情况，不得宣称完成或发布：

- `typecheck`、全量测试或 build 失败。
- SQL 写操作可能被错误放行。
- 文件路径可能越界或静默覆盖。
- SQL INSERT 在特殊标识符或特殊值下不能执行。
- 查询取消后连接未释放或错误写入历史。
- Windows Electron 核心旅程未执行。
- better-sqlite3 ABI 未确认。
- 日志输出密码、API Key 或完整敏感 SQL。
- 文档状态与实际代码/测试证据不一致。

## 4. 回退要求

- 变更前记录 `git status` 和基线提交。
- 每个阶段保持独立提交或清晰 diff。
- 失败优先回退当前阶段，不回退用户已有改动。
- 不删除用户数据目录、不用重装依赖掩盖根因。
- 数据格式变更必须先提供兼容读取或迁移回退方案。
