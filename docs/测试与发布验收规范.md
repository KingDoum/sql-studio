# SQL Studio 测试与发布验收规范

> 用途：统一 SQL Studio 的测试分层、真实环境验证、发布阻断条件和回退要求。
> 待办与当前未完成项见 `docs/待办与遗留问题.md`，本文件只定义"怎么验"。

## 1. 验证分层

### L1：静态与类型

- `npm run typecheck`
- 检查共享类型、IPC channel、路径和依赖边界。
- 失败时不得进入下一阶段。

### L2：单元与组件

- `npm test`
- Main、Renderer、Shared 测试必须同时执行。
- 记录实际测试文件数、用例数、失败用例和环境信息。

### L3：构建

- `npm run build`
- 确认 Main、Preload、Renderer 产物生成（`dist/main/main.cjs`、`dist/main/preload.cjs`、`dist/renderer/index.html`）。
- 确认 preload 使用 `preload.cjs`，生产 Renderer 不依赖 CDN。

### L4：无头 E2E（Playwright，需先 `npm run build`）

```bash
node tests/e2e/ui-layout-check.mjs                    # 四窗口尺寸无横向溢出 + 工具栏/拖拽条/Modal
node tests/e2e/ui-state-check.mjs                     # 执行中 / 错误 / 截断状态
node tests/e2e/scroll-check.mjs                       # 20 列横滚 / 30 列预览 / 500 行 / 20 库 / 40 字段 / 0 行多列
node tests/e2e/appearance-and-rate-limit-check.mjs    # 三主题 + 限流参数读写 + provider 日志
node tests/e2e/workspace-recovery-check.mjs           # 恢复标签/脏点/不写文件/防抖 latest-wins/坏快照降级
node tests/e2e/s2-dom-probe.mjs                       # 顶栏/状态栏 DOM 探测
```

无头 E2E 使用 mock `window.sqlStudio`，**不能替代** L5。

### L5：真实 Electron 与数据库

必须在 Windows 图形环境和可用 MySQL/MariaDB 测试库执行，完整清单见 `e2e-checklist.md`：

- 启动打包产物或 `npm run dev`。
- 新增、测试、保存、切换和删除连接。
- Schema 懒加载、表/字段双击行为、数据预览。
- 单语句、多语句、读写混合、CTE、CALL、取消和截断。
- 历史、收藏、打开、保存、另存为（含取消/覆盖/无权限）。
- Excel、CSV、SQL INSERT 导出。
- AI 补全（真实 Key）、三主题切换、自动保存与恢复、持久日志轮转。

### L6：打包产物

- `npm run package`（或本地 `--dir` 快速版）产出 `release/` 产物。
- 安装/解压后启动，确认 `%APPDATA%\SQL Studio\logs\main.log` 出现 `app.starting` 与 `db.ready`。
- 确认原生模块（better-sqlite3）为 Electron ABI。

## 2. 每次代码变更的证据

每个阶段报告必须包含：

- 修改文件和未修改的边界文件。
- 行为变化和兼容性说明。
- 运行的命令及退出码。
- 实际测试文件/用例统计。
- 真实环境、Node、npm、Electron、数据库版本。
- 截图、日志或数据库结果等必要证据。
- 已知限制、回退方式和下一步决策门。

## 3. 发布阻断条件

出现以下任一情况，不得宣称完成或发布：

- `typecheck`、全量测试或 build 失败。
- SQL 写操作可能被错误放行。
- 文件路径可能越界或静默覆盖。
- SQL INSERT 在特殊标识符或特殊值下不能执行。
- 查询取消后连接未释放或错误写入历史。
- 自动保存写入真实 `.sql` 文件，或把密码/API Key 写入快照。
- 日志输出密码、API Key 或完整敏感 SQL。
- better-sqlite3 ABI 未确认。
- Windows Electron 核心旅程未执行（见 `待办与遗留问题.md` P0）。
- 打包产物无法启动。
- 文档状态与实际代码/测试证据不一致。

## 4. 回退要求

- 变更前记录 `git status` 和基线提交。
- 每个阶段保持独立提交或清晰 diff。
- 失败优先回退当前阶段，不回退用户已有改动。
- 不删除用户数据目录、不用重装依赖掩盖根因。
- 数据格式变更必须先提供兼容读取或迁移回退方案（SQLite schema 迁移必须显式、单事务、幂等）。
- 原生模块 ABI 变更（如 `electron-builder` 重建后）按 `开发文档.md` §11.3 恢复。

## 6. 最终发布门

以下项目全部通过后，才允许标记本轮完成：

- `npm run typecheck`
- `npm test`
- `npm run build`
- 相关无头 E2E（L4 全部脚本）
- Windows Electron GUI 冒烟（`e2e-checklist.md`）
- MySQL/MariaDB 真实查询与取消冒烟
- 收藏和文件路径回归
- SQL/CSV 导出回归
- 自动保存/恢复与持久日志回归
- 打包产物安装并启动
- 安全日志检查（无密码/API Key/完整 SQL）
- `待办与遗留问题.md` 中所有 P0 项已关闭
